English overview: establish a small reproducible baseline, prioritize conversion-context reuse,
sampling before pixel conversion and preprocessing allocation/copy reduction, then deepen
queue/recovery checks, language/profile integration and opt-in adaptive batching.
Soak and fault-injection checks accompany these stages. Native decode/inference hardware
discovery and policy-driven selection are now priority H2/H5 work; network camera discovery,
additional platforms and specialized backends remain extensions. This roadmap is not a claim
that planned capabilities are implemented or production-accepted.

## 1. 目标与边界

围绕“采集 → 解码 → 前处理 → 推理 → 结果消费”提高可预测性、效率和接入体验。
优先处理实测瓶颈，不以增加功能数量衡量成果。

- 延续 Media SDK、Vision SDK 两组件及共享公共层，不为此次优化新增第三个 DLL。
- SDK 提供底层采集、处理、资源控制和诊断能力；设备台账、凭据持久化、业务规则、
  报警处理、存储和 UI 仍由宿主负责。诊断事件不扩展成业务报警中心。
- Windows x64 CPU 是现有验收起点；GPU、硬解、其他系统、Java 与移动端不因写入路线图而获得支持承诺。
- 延续有限预算、明确所有权、显式错误、可查询结果和关闭排空，性能不能以破坏这些约束换取。
- 本路线最初整理为文档规划；现获授权在 SDK 内实施与隔离负载验证，按需修订合同及来源覆盖清单，仍不覆盖历史冻结或标签、不操作现场相机或发布。

## 3. 分阶段范围与验收

### R1：最小观测与性能基线（最先实施）

目标：解释延迟和资源消耗来自哪里，让 R2 能尽快开始；不先建设完整监控平台。
先满足固定负载、分段计时、计数和前后对比四项即可；更丰富的事件整理随 R3/R5 补齐。

范围：

- 定义帧序号、流代次、模型身份和请求 ID 的关联；多路和同帧多模型不能串结果。
- 记录接收、解码、入队、出队、前处理、执行、结果可取及消费各时间边界。
  SDK 内端到端延迟与设备曝光到显示的延迟分开；不同钟域不直接相减。
- 统计 P50/P95/P99、帧龄、有效吞吐、队列峰值、丢弃/拒绝原因、内存、线程和外部持有量。
  不适用或不可测标为未知，不用零值冒充耗时为零。
- 优先由基准工具聚合已有指标；新增 SDK 观测采用可关闭、采样且有界的方式。
  不引入监控服务依赖，不在采集/推理热路径同步写文件。

验收要求：

1. 提供可复现负载：单路、预算内并发、超预算三档；固定图片/视频指纹、尺寸、格式、
   采样率、模型及消费者速度。并发档位是测试输入，不是承诺支持路数。
2. 结果绑定源码与 DLL 指纹、工具链、运行库/实际后端、硬件、配置、预热规则和样本数。
   明确吞吐分母、丢帧口径及分位数算法；样本不足时不声称可靠 P99。
3. 队列及帧关联可用于定位至少一次人为注入的慢消费或慢推理；不得把播放器预测结果算成新推理。
4. 对比观测开启/关闭的开销；结项记录测量波动范围，并为各负载选定帧龄、截止时间、
   内存/线程预算和后续性能回归容差。未测量前不预设“提速百分比”。

### R2：优先优化转换、采样与前处理热路径

**新增前置 H2：硬件解码。** R1 后先落实探测和选择合同及实际接线，D3D11VA 优先、DXVA2 为构建可用时的兼容候选；覆盖直接压缩数据解码与 RTSP 像素订阅。明确编译支持、硬件发现、依赖、初始化和目标码流输出五层状态，不以设备名或“prefer hardware”宣称正在硬解。压缩直传不为探测而启动解码器。

验收：H.264/H.265 尺寸/profile/位深、无设备/依赖/不支持格式诊断、CPU 回退、暂时故障重试、关键帧恢复、活帧与关闭安全；同预算对比有效交付率、CPU、显存、回读成本和 P95。缺目标设备标未验，不以软件模拟证明真实硬解。浏览器看板的 WebCodecs 提示与自动降级属于宿主显示层，SDK 完成不会自动修复该页面。本次不改 AM-RT。

依赖：R1 最小基线可复现，已有预算、租约和关闭约束保持有效。
不等待 R3 的完整长跑后才开始这些局部优化；发现底层安全缺口时先修复该前置问题。
只优化有证据的路径，不先承诺全链路零拷贝。同进程优先安全引用复用，
跨进程共享帧继续可选；保留解码缓冲 → SDK 帧 → 共享池 → 张量 → 语言视图的复制/分配图。
按下列顺序分成可回退小包：

| 顺序/ID | 待优化项及当前证据 | 参考 | 必测的机制指标与正确性 |
| --- | --- | --- | --- |
| R2-1 | [copy_pixels](../crates/am-camera/src/media/codec.rs) 每次分配输出并创建/释放 SwsContext；优先缓存转换上下文，再评估受控缓冲复用 | REF-A1 | 上下文创建/释放次数、输出分配次数与字节/帧、转换耗时；稳定格式下创建不再随帧数线性增加，格式变化只在需要时重建 |
| R2-2 | [emit_decoded](../crates/camera-ffi/src/subscriptions/hub.rs) 先物化 RGBA，[fanout](../crates/camera-ffi/src/subscriptions/pixels.rs) 后判断订阅到期；把昂贵像素转换的需求判断尽量前移 | REF-W1 | 实际解码帧数、像素转换次数、交付次数、有效采样率；无到期像素消费者时避免无用转换，预览与控制通知不被误停 |
| R2-3 | [prepare](../crates/vision/src/sdk/prepare.rs) 生成浮点数组，[TensorData::new](../crates/vision/src/sdk/model.rs) 再分配并复制；先减少中间复制，再评估安全工作区与 SIMD | REF-A2/REF-P1 | 张量分配次数/字节、复制字节/帧、前处理耗时；目标路径取消可避免的临时数组到最终张量复制，保持对齐、并发安全和输出坐标合同 |
| R2-4（条件项） | 减少共享帧发布、缩放输出和 C#/Python 搬运；必要颜色/布局转换单独列账 | REF-A1/REF-P3 | 先列当前复制图；只有仍属实测热点且前三项收益可复现时纳入，否则转后续候选，不阻塞 R2 收口 |

验收要求：

1. 每个小包都按第 4 节量化，分别记录机制计数、局部耗时和端到端变化；
   没有实测数据不得勾选“性能优化完成”，没有收益也须保留结果。
2. R2-1 的结构性目标示例：单会话、单转换路径、格式固定的 N 帧，
   上下文应由逐帧创建变为初始化创建一次、关闭释放一次；重连/重配另计。
   这是待验目标，不是已测结果；仍须核对转换耗时和整体收益。
   覆盖同格式长序列、分辨率/像素格式切换、重连、消费者持帧及缓冲池耗尽。
   活缓冲不得覆写；复用池和兜底分配都计入预算，不能直接照搬 AIMM 的分配兜底。
3. R2-2 至少覆盖输入 30 FPS、目标 5/10/30 FPS，以及混合采样、多消费者和无到期消费者。
   对比同一输入的转换次数与 CPU；按有效输入窗口验证交付率，不许靠少交付伪装提速。
   H.264/H.265 参考链继续完整解码或显式重同步，不能将少做颜色转换写成少做参考帧解码。
4. R2-3 覆盖既有支持的输入格式、缩放/填充/裁切、通道顺序、布局及分辨率；
   对拍像素/张量、反映射坐标和真实模型结果。SIMD 误差界限须预先定义并核对阈值附近输出，
   不把 AIMM 的数值容差直接作为 FrameBraid 验收值。模型缺失则保留对应未验项。
5. 覆盖异步推理、调用方提前归还、消费者退出、关闭竞争及槽位耗尽；
   活租约不因超时强收，并发请求不能共享可变工作区造成串帧。
6. 在相同有效交付率下报告 CPU、内存、延迟、有效吞吐及分配/复制量。
   P95/P99、预算与关闭行为不超出 R1 确定的容差；只改变代码形式或收益落在噪声内，
   不算已证明性能提升，需简化、回退或注明仅完成机制改造。

### R3：队列、重连与故障恢复深化

依赖：R1 基线与预算、R2 已交付热路径候选。目标是在压力下保持结果新鲜和资源有界。
R2 必需的生命周期与背压定向测试不能延后；这里补齐跨队列、组合故障和长跑验证。

范围：

- 分别定义采集帧、压缩包、实时推理、离线批量、结果和控制通知的满载处理。
  压缩包丢弃须保持或重建解码参考链，不能照搬独立图片的任意丢旧策略。
- 统一过期判断、源代次变化、重连退避、慢消费者隔离及回调退出屏障。
- 已接受请求在约定查询窗口内有成功/失败/取消/过期等明确状态；满载拒绝不能伪装已接受。
- 不用无限缓存、无限重试或每帧增建线程处理压力；回调变慢不能拖死整个管线。
- 借鉴 REF-W2 的分批投递方式时，同时约束线程到事件循环的暂存队列；
  队列数量、字节和外部持有须覆盖整条路径，不能只限制最后一级。
- 借鉴 REF-A4 的并发退出与 REF-P3 的槽位持有用例，不移入业务事件总线或进程管理器。

验收要求：

1. 覆盖过载、慢回调、结果长期不取、断流、认证失败和反复重连；计数与处置原因可对账。
2. 按 R1 预算验证队列、字节与 SDK 可控线程上限。原生库/驱动内存与 SDK 可控预算分列，
   不承诺外部库 RSS 可由 SDK 硬性限制。
3. 压力解除后在既定恢复窗口内恢复有效处理，队列不持续积压；新代次不混入旧帧/旧结果。
4. 定向候选至少验证 20 次断流恢复、100 次启动/关闭循环；记录失败和重试，关闭排空后无迟到回调。
   次数是测试覆盖要求，不是长期稳定性证明。

### R4：跨语言接入与模型档案完善

依赖：前面阶段形成稳定的所有权、错误及统计语义；可先整理需求，但不并行扩张接口。

范围：

- 完善 C#/Python 常用采集与推理流程、错误诊断、结果释放、取消和关闭指导。
  保留底层 API；高层封装不偷偷增加第二层无界队列。
- 明确复制式输出与借用视图：借用须有明确拥有者、只读约束和有效期，不依赖 GC 时机来保障帧安全。
- 统一 profile 版本、模型摘要、前后处理配置及输入输出诊断；仍限定明确模型版本/导出档案，
  不承诺所有 YOLO 模型通用，不建设云端模型注册中心。

验收要求：

1. C/C++、C#、Python 示例从干净解压的匹配 SDK 包运行，覆盖成功、缺依赖、形状错误、背压和关闭。
2. 多模型、异步回调和借用视图不发生串帧、泄漏、二次释放或释放后读取；误用有明确诊断或使用约束。
3. 五类档案分别准备合法取得的代表模型，绑定权重摘要和导出配置，核对预处理与实际输出。
   外部模型缺失时保留未验项，不能用 Identity 图或单测代替五类真实模型端到端验收。
4. 档案更新有兼容矩阵和不兼容错误；头文件、语言封装、能力查询及示例保持匹配。

### R5：条件化 batching 与后端调度

**新增前置 H5：推理硬件探测与自动选择。** 只依赖 R1 最小基线和现有模型合同，与第 1 组调度优先推进。分别核硬件、依赖、provider、目标模型会话及真实执行；按调用方允许列表、优先级与 strict/fallback 约束选择 CPU/OpenVINO/CUDA，报告请求/实际后端、设备、原因及未验状态。OpenVINO 当前 CPU 及单加速后端共存约束不变。查询只读，探测/刷新有界，暂时失败可显式重试；不每帧切后端、不重放已完成或状态不确定请求、不宣称自动选择一定最快。设备忙、缺依赖、不兼容、运行期故障和关闭须定向测试，实际加速效果按设备分别验收。

其余自适应组批及联合调度依赖 R1～R4 有实测基线和明确模型合同。目标是验证有收益的调度，不默认改变实时策略。

范围：

- 自适应组批显式启用，仅组合兼容模型版本、后端、形状及前处理约定的请求。
  设置最大批次、等待窗口、截止时间及总资源预算；实时与离线用途分开。
- 不从动态尺寸猜 batch 轴，不擅自给固定 batch 补虚假样本；不满足条件时沿用已声明的拒绝/回退合同。
- 借鉴 REF-A3/REF-P2，以有效检测帧率与实测模型容量评估准入；固定 batch=1 不为凑批等待，
  实时请求与有序/离线请求分别验证公平性。不照搬默认容量、线程数或自动降帧规则，
  不静默降低调用方的检测帧率；后端切换或增加模型实例须有资源证据。
- 后端选择与切换受调用方策略和能力/资源检查约束；报告实际后端、切换原因和恢复状态。
  不静默重放已完成请求，也不因切换重置帧身份或扩大线程预算。

验收要求：

1. 在兼容的代表模型和多路负载上，对比开启/关闭后的吞吐、等待、P95/P99、帧龄及内存。
   吞吐增加但违反实时延迟预算不能认定为实时优化通过。
2. 覆盖不满批、固定/动态 batch、不兼容形状、过期、取消和并发公平性，逐项回执及结果关联保持正确。
3. 覆盖后端缺失、初始化失败、竞争和允许的回退；未具备 GPU/加速器环境的项目继续标未验。
4. 新调度可关闭并回到既有策略；回退不能隐瞒失败或造成重复完成。

## 4. 性能量化合同：实施时必须执行

以下是后续实施的验收要求，本轮未跑基准。区分三类结果：
**机制计数变化、局部耗时收益、端到端收益**；前者不能自动证明后两者。
参考项目的历史数字不直接写成 FrameBraid 指标，也不预先承诺提速百分比。

| 测量对象 | 最少记录 | 对照条件 |
| --- | --- | --- |
| R2-1 转换上下文/图像缓冲 | context 创建/销毁次数、分配次数/字节每帧、转换 P50/P95/P99、池命中/耗尽/兜底次数及常驻字节 | 同一压缩输入、分辨率、格式、输出尺寸和有效交付率；单独测格式切换与持帧 |
| R2-2 采样前移 | 接收/解码/像素转换/交付帧数、源时间跨度、采样偏差、丢弃原因、CPU 与帧龄 | 同一 30 FPS 样本分别配置 5/10/30 FPS；视频预览是否开启及消费者组合固定 |
| R2-3 张量路径 | 分配/复制次数与字节每帧、前处理及模型执行分段耗时、张量误差、结果差异 | 同图/模型/导出档案/形状/后端/线程/预热；分别覆盖典型 720p/1080p 与既有格式 |
| R3 压力/恢复 | 各级队列峰值、总暂存字节、拒绝/丢弃/过期、回调耗时、断流到恢复首个有效结果耗时、资源趋势 | 输入速率、并发档位、慢消费时间和故障时刻可重复；健康消费者单独统计 |
| R5 调度/组批 | 成功有效吞吐、入队等待/组批等待/模型耗时、逐帧总等待、截止时间违约率和各路公平性 | 同模型/负载/总预算开关对照；批次总耗时除以 batch 大小仅是吞吐折算，不是单帧等待时间 |

共同规则：

1. 先保存改前基线，再测候选；绑定源码/DLL 摘要、运行库、实际后端、硬件、电源模式、
   输入/模型摘要、配置、计时边界、预热、样本数与丢帧口径。FFmpeg/ORT 内部开销与 SDK 自控开销分列。
2. 同机交替执行基线/候选，建议至少 3 轮稳定段；记录每轮原始结果、离散程度和重复性。
   微基准与整链路分别报告，保留观测开关对照；样本量不足的 P99 标为不具代表性。
3. CPU 说明是单核百分比还是整机归一口径；内存分别报告进程私有内存/RSS、
   SDK 池/队列/外部持有及峰值，不把释放后 RSS 未下降直接判为泄漏或判为无泄漏。
4. 统一摘要表字段：`优化 ID / 基线与候选提交 / 负载 / 指标及单位 / 改前 / 改后 / 差值与比例 / 波动 / 正确性 / 未验项`。
   时间或资源下降比例采用 `(改前-改后)/改前`，吞吐提升单列；零分母不计算比例。
5. R1 在改动前约定性能回归容差和资源/时延预算，不在看到结果后调门槛。
   接受性能优化须有目标指标可重复、超过波动的改善，且正确性与非目标指标符合预算；
   未达到时报告原因，不能靠放宽画质、少交帧、删校验或延后统计边界得到“通过”。
6. 小包只跑相关基准与定向测试；候选整体验证再按第 5 节长跑，不每次局部调整重跑全量。
   原始精简数值与候选指纹单独留存；公开前清除设备地址、凭据、业务图片等敏感内容。

## 5. 持续运行与故障注入：贯穿各阶段

优先构造可控故障和核对恢复结果，不以“跑了一段时间没崩”代替机制验证。

| 故障/压力 | 需要观察的结果 | 主要阶段 |
| --- | --- | --- |
| 网络抖动、断流、认证失效 | 有界退避、状态明确、不忙循环，恢复后代次正确 | R3 |
| 慢消费者、慢回调、结果不取 | 背压/丢弃有原因，队列与外部持有分别可见，正常消费者不被拖死 | R1/R3 |
| 持有共享帧不归还、消费者异常退出 | 不覆写活槽位、不释放后使用；拒绝/故障退化符合合同 | R2/R3 |
| 模型无效、运行库缺失、推理失败 | 错误可定位、失败责任可查询，不崩溃或假成功 | R4/R5 |
| 高并发、关闭时仍有请求、反复装卸 | 截止时间有效、请求收口、回调排空、SDK 对象回收 | R2～R5 |
| 观测消费端停滞或关闭观测 | 指标通道有界，数据处理不依赖监控端在线 | R1/R3 |

验证分层：

- **日常改动**：最小受影响测试及编译/合同检查；文档改动只做内容、引用与不变项核对。
- **阶段候选**：固定基线负载、相关故障注入和新旧结果对比。因新增失败再扩大验证，不循环跑无变化全量。
- **关键稳定性候选**：建议在 R2 内存路径候选、R3 完整恢复候选运行至少 4 小时混合负载；
  同一候选同时覆盖两个阶段时可合并一次，报告不能冒充另一候选结果。
- **生产试用前候选**：至少一次 24 小时代表负载，包含压力、故障注入和恢复段。
  这些时长是拟定验收要求，不是 SLA，也不取代现场试用。

长跑须报告预热与稳定段的内存/句柄/线程趋势、尾延迟、失败/恢复次数、队列与外部持有量。
不能仅用首尾内存差证明无泄漏；异常增长应给出归属和解释。底层库允许常驻，不等于 SDK 对象可无限累积。

样本、故障注入与测试库使用隔离目录/随机本机端口；实机操作需另行授权。
结束后回收生成的大样本及测试副本，保留精简原始数值、日志、摘要和源码/制品指纹。
归档无法取得时标明证据缺口，不把摘要当成原始日志仍存在的证明。
