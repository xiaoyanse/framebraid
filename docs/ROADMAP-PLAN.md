# v0.3+ 统一排期计划（2026-10-28 与用户对齐）

> 一页纸排期。五条主线显式排序，资源冲突按序裁剪。OpenSpec 逐项管理，媒体侧与推理侧并行。

## 主线 1：推理引擎多元化（用户指定最优先）

| 批次 | 内容 | 量级 | 依赖 |
| --- | --- | --- | --- |
| E2 | DirectML 枚举扩展（ABI 加枚举值+生成器+运行库实测） | **1 周** | 无（运行库已验证可载） |
| E1 | OpenVINO 原生引擎接入（多引擎抽象+OpenVINO C API 绑定+五档案适配，参考 aimm 已验证路线） | 2~3 周 | E2 定义的枚举模式 |
| M5 | 动态换模型（运行中热切换不重启） | 1 周 | E1 引擎抽象落定 |

**验收**：CPU/CUDA/OpenVINO/DirectML 四路径各自真实推理通过+矩阵 verified+对拍容差。

## 主线 2：零回读显存管线（M2，与主线 1 并行）

| 批次 | 内容 | 量级 | 依赖 |
| --- | --- | --- | --- |
| M2a | 媒体侧 GPU 帧订阅+显存帧池（am-camera/camera-ffi 域，**与 E1 无代码冲突可真并行**） | 2 周 | 前置调研已全通 |
| M2b | Vision 侧接线（CUDA 互操作+IOBinding 绑定 GPU 帧） | 2 周 | M2a + E1 抽象落定 |
| M2c | **搬运审计指标**（新吸纳：验收必须回答"每帧几次拷贝/多少字节"并证明减少）+ CPU 卸载实测 | 1 周 | M2b |
| M3 | Intel 路径+回退矩阵完备（无 GPU 机器亦稳） | 2 周 | M2c |

**验收**：端到端零回读 + 搬运审计数字对比 + CPU 卸载从"未证"变"已证"。

## 主线 3：媒体 IO 扩展（第一批 A/F 归位）

| 批次 | 内容 | 量级 | 依赖 |
| --- | --- | --- | --- |
| A | 离线录像文件分析（文件源+seek→解码→推理） | 1 周 | 无（可与 E1 并行） |
| F | 帧抓图编码输出（JPEG/PNG） | 0.5 周 | M2a 编码底座 |
| ⑤ | 编码推流（RTMP/MP4 存档，GPU 编码器复用） | 2 周 | M2b |

## 主线 4：平台与分发

⑥ Linux 移植（随 M2 跨后端设计）、⑦ 包管理器分发（PyPI/NuGet/crates.io）。M2/M3 完成后启动，各 2~3 周。

## 主线 5：场景扩展（按需触发，不预先排期）

GB28181 客户端 / ONVIF 发现+取流 / 跨帧跟踪 / ROI 裁剪推理 / 多模型流水线 / ARM64——业务需要时从待实现池取用立项。

## 排序理由（冲突裁决）

1. E2 先于 E1：量级差 3 倍，先拿快速战果且定义枚举模式
2. M2 媒体侧先行、vision 侧等 E1：避免同一 executor/session 域双线改动返工
3. A 与 E1 并行：分属 am-camera 与 vision 两个 crate，零冲突
4. F/⑤ 依赖 M2 编码底座：一次编码器投资三处收益（F/⑤/未来录制）
5. M4 Jetson：真机到位后随时插入（无前置依赖）

## 场景视图（消费方工作流优先级，2026-10-30 增）

从消费方工作流看同一份排期：多路接入→检测→编码输出→运维观测。
每段映射既有批次；发版门禁按 RELEASE_CHECKLIST 基线与场景要件全跑，
执行口径与豁免见 VERIFICATION_DOCTRINE.md。

| 消费方阶段 | 消费方问题 | 映射批次 | 锚点 |
|---|---|---|---|
| 多路接入 | 多路并发稳不稳？节拍准不准？ | 主线 2（M2a/M3）、既有 ISAPI/RTSP/MJPEG 通道 | 基线：节拍精度/多路线性度；场景：R2 节拍、R7 MJPEG 流、R8 断流可观测 |
| 检测 | 推理快不快？换模型要重启吗？ | 主线 1（E2/E1/M5）、M2b/M2c | 场景：R9 绑定装载；基线：解码配对守解码底座 |
| 编码输出 | 抓图/存档/推流顺不顺？ | 主线 3（F/⑤）、A 离线分析 | 场景：R1 4K 预算边界（编码侧输入档） |
| 运维观测 | 坏源/断流看得见吗？ | M2c 搬运审计 + V1 场景库自身 | 场景：R8 断流可观测；基线漂移=发布阻断即观测兜底 |
