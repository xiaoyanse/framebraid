# GPU 全程管线设计（v0.3 主线，2026-10-28）

负责人 2026-10-28 批准启动第二批（GPU 主线）后先行的方案设计；实现前按本仓规则合同先行、逐里程碑 MET-2 验收。本设计覆盖：全程显存管线（B 档）、CUDA/OpenVINO 推理验收（①）、运行期模型热切换（③）。

## 1. 目标与成功判据

- **主目标**：解码→预处理→推理全程 GPU 显存直通，CPU 仅处理小结果张量；相同交付合同下进程 CPU 时间相对现 CPU 路径**可测地下降**（CPU 卸载从"未证"变"已证"）。
- **保护指标**（MET-2）：输出一致性（GPU/CPU 双路对拍，容差进合同）、交付帧龄、显存字节预算与租约、关闭/取消语义不回退。
- **非目标**：不承诺所有 GPU 路径单帧更快；不改 CPU 路径既有语义；不含浏览器播放。

## 2. 现状与差距（代码级接点）

| 接点 | 现状 | B 档差距 |
| --- | --- | --- |
| 解码输出 | D3D11VA/DXVA2 硬解后经 `media/codec/readback.rs` 回读为 CPU RGBA（计费回读预算）——S1~四路负结论根源 | 硬解纹理**不回读**，以 GPU 帧句柄出 SDK |
| 前处理 | `vision/sdk/prepare.rs` CPU 直写对齐张量（RG 表/NV12 转换，R2 优化成果） | GPU 侧等价变换（缩放/色转/布局），CPU 版保留为回退与对拍基准 |
| 推理输入 | executor 组 CPU 张量 → ORT 会话输入（复制进 ORT） | ORT IOBinding 绑定 GPU 缓冲；CUDA EP / OpenVINO GPU 验收 |
| 跨库交接 | Media→Vision 以 CPU 像素交接（订阅/共享池） | GPU 帧跨库句柄语义（共享池扩展），CPU 帧路径原样保留 |

## 3. 分层架构

- **L1 GPU 帧对象**：媒体侧输出的不透明 GPU 帧句柄（Windows=D3D11 纹理引用；Jetson=EGLImage/CUDA 缓冲；跨库经 ABI 传递，仅 SDK 间可用，宿主不可解析内里）。
- **L2 媒体 GPU 输出**：硬解路径旁路 readback，像素订阅新增 GPU 帧模式（CPU 订阅照旧走回读，双模式并存）；GPU 帧进显存帧池。
- **L3 GPU 前处理**：NV12→张量、缩放、NHWC/NCHW 布局三件事在 GPU 完成；Windows NVIDIA 用 CUDA kernel（D3D11↔CUDA 互操作），Intel 侧随 OpenVINO 远端上下文评估，Jetson 统一内存天然简化。**输出必须与 CPU 版对拍**（容差入合同，RGB→YUV 系非逐位可保，容差与对拍方法先立合同）。
- **L4 推理 IOBinding**：ORT CUDA EP 绑定 L3 输出缓冲；OpenVINO EP 按 remote context。结果张量小，回 CPU。
- **L5 显存预算**：R3 的预算/租约/池语义延伸到 GPU：GPU 帧池上限、显存字节计费、借出归还、关闭排空——复用现有 Charge/池骨架，按资源类目分账。
- **回退矩阵（合同必写）**：无 GPU / 驱动不可用 / EP 加载失败 / 显存不足 → 逐级回退到 CPU 路径，行为与今日一致；探测/分层状态沿用 H2.1/H5.1 五层语义，新增"GPU 管线可用"能力位。

## 4. ABI 演进（兼容新增红线）

- 新增：GPU 帧视图/池/查询导出、推理 GPU 输入绑定、能力位与诊断扩展；既有结构与语义**零改动**（1.0/1.1 调用方不受影响，合同先行、生成器同步、冻结链照常）。
- 攒批/调度/通知/租约/关闭在 GPU 输入上语义不变（攒批的聚合键追加"帧资源类目"维度）。

## 5. 里程碑（每步独立可验收、可停）

| # | 内容 | 量级 | 验收门 |
| --- | --- | --- | --- |
| M1=① | CUDA+OpenVINO **推理验收**（本机 RTX 5060 / Arc 140T）：装运行库，现有分层选择跑通真实 GPU 推理，CPU 帧输入+IOBinding 第一层 | 周级 | 双后端真实推理通过+MET-2 三轮；CPU↔GPU 输出对拍立容差 |
| M2 | Windows NVIDIA **端到端零回读**（D3D11→CUDA 前处理→CUDA EP） | 月级重心 | CPU 卸载可证（对比 S1/四路基线）；显存预算/回退矩阵生效 |
| M3 | Intel/OpenVINO 路径 + 回退矩阵完备（CPU-only 机器亦稳） | 数周 | 分层状态与回退实测 |
| M4 | Jetson 统一路径 | 需真机 | 真机 MET-2 |
| M5=③ | 模型热切换（换权重/档案不重启、在途请求不中断） | 周级，可并行 | 热切换回归+输出一致性 |

执行顺序：M1 → M2（M5 并行）→ M3 → M4。每步前合同与生成物先行；OpenSpec 以新 change 立项管理。

## 6. 影响评估（负责人核心关切）

- **ABI 面：无破坏**。全部为兼容新增，旧调用零影响；ABI 主版本不动。
- **内部改动面：大而分层**。涉及 am-camera(codec/hardware)、camera-ffi(订阅/池)、vision(prepare/executor/backend)、sdk-support(池/预算)、sdk-abi+生成器——但改动集中在**数据面**（帧的形态与搬运），**语义面**（调度/攒批/通知/租约/关闭/预算框架）复用不动，这是前期 R3/R5 分层带来的结构性红利。
- **可回退性**：CPU 双模式并存到 M3 收口前；任一里程碑失败可停在该步，SDK 仍完整可用。
- **主要风险**：D3D11↔CUDA 互操作细节、ORT IOBinding 的 EP 约束、GPU 侧对拍容差确立、Jetson 真机排期；均有对应缓解（M1 先立对拍容差、回退矩阵兜底、M4 前不依赖真机）。
- **量化预期翻转**：S1~四路的"硬解不省 CPU"负结论限定于回读合同；GPU 管线落地后同合同重测，预期 CPU 卸载显现——新结论按 MET-2 新目标卡，不覆盖历史记录。
