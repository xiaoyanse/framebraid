# H5 推理后端发现、选择与恢复

本地实施合同，2026-10-26；SDK main串行，不修改AM-RT、不发布。C ABI 1.0/1.1旧布局不变；Rust核心先接线，再兼容扩展DLL导出和语言封装，不能把Rust原语当跨语言整包完成。

## 分层与策略

- CPU、OpenVINO:CPU、CUDA分别区分：设备信息、依赖候选、运行库编译支持、provider注册、目标模型会话、真实Run成功。编译有某EP不证明依赖齐全；文件存在不证明能加载。CUDA ordinal不等同视频DXGI索引/LUID。
- Rust `BackendSelectionPolicy`为有序允许列表，最多3项，候选由backend及CUDA device_id组成；非CUDA设备号必须0，无重复候选。`allow_fallback=false`只尝试首项；即使允许回退，CPU也必须列在允许列表，不能悄悄添加。旧load的requested/strict语义保留，仍仅退CPU，backendConflict保持旧错误。
- 新选择入口有1..5000ms候选会话选择软预算（从首个候选开始，不含之前的文件读取/档案校验及之后的I/O验证），候选调用之间检查，最长3次会话尝试；原生调用不可中断，不能宣称硬超时。成功后不后台测速/换后端。文件/模型/档案/输入约定错误立即停止，不把换设备当修模型；后端不支持或冲突可按新允许列表继续，报告每次阶段、稳定错误键及可用的原生错误码，报告不复制可能含路径/地址的原生消息；ORT自身logger仍受其环境配置控制，本组不修改共享logger。
- 会话设置明确禁用ORT环境默认EP，防止请求CPU却继承宿主CUDA；使用独立且受既有预算约束的会话线程池。进程只容纳一种加速后端与CPU；provider注册可能部分装载后失败时，保守保留该加速域，不允许偷偷装另一种。仍可重试同后端或CPU，不永久缓存一次失败。
- 后端状态锁只保护短小的域认领/记账，不跨provider注册或模型构造持有；构造慢不能阻塞已在运行模型的完成记账或普通状态读取。

## 真实执行与故障

2026-10-27逐候选准入修订：新有序选择不预占整张列表中最昂贵后端的线程。先保留各候选共用的ORT基础额度；每次原生构造前只按该候选增减预留，OpenVINO额外线程也计入。准入失败以`resource_admission`阶段、`sdk.resourceExhausted`入报告，只有显式允许回退才继续下一允许候选。旧候选原生构造返回并释放其失败资源后才调整下一候选，不能把取消或超时当原生已退出。全局/模型/control共同准入失败仍拒绝，不额外创建执行器绕预算；legacy加载行为保持。Rust新增`Model::load_selected_admitted`帮助入口由宿主提供短小准入函数，现有load/load_selected默认无外部准入而保持兼容。见[本轮目标与验证](../verification/sdk-h5-resource-admission-20261027.md)。

模型拥有选择快照，查询不调用驱动、不创建模型、不改探测时间。Session成功与Run成功分开，记录成功/失败次数、最近原生错误；公开可修改的旧actual_backend字段不作为执行记账的可信来源。EP会话执行成功不证明所有节点都在GPU，未做节点放置验证时明确placement_verified=false，不用子图未知值-1冒充全部加速。

选择在调用方显式初始化的同一ORT运行库内进行，不能从CPU版运行库自动切到另一份GPU版；运行库候选装配及C缓存查询仍待后续接线。路径模型及其外部权重在加载期间由调用方保证不被修改。

运行期失败只将当前请求失败并保留诊断，不自动重放已接受输入或在读缓冲。后续DLL恢复需要排空/模型重建合同、请求唯一终态和预算验证；首组核心接线不关闭H5.3。设备发现必须显式、有界、单轮准入，驱动调用间检查软预算；CPU/平台未知/缺驱动/驱动调用失败分别表示。只读缓存接口和C导出在后续组实际接线后交付，旧矩阵语义另行核对，不导出空壳。

## 性能验收口径

统一按[MET-2](../PERFORMANCE_ACCEPTANCE.md)：策略正确与目标模型真实可用是H5主目标，跨后端资源/延迟是取舍，不要求GPU或硬解单帧更快。调度另以等待/过期/公平性或离线有效吞吐为主；CPU时间、GPU相关引擎及保护预算按场景采集。历史5%标签保留待复核，不是统一验收门槛，不据未知资源指标推断卸载收益。

R2已记录硬解到RGBA较慢，只是本机整段耗时事实，不单独认定缺陷。需要继续量化是否降低CPU压力、是否满足业务延迟与并发预算。共享显存带宽/功耗意味着解码专用单元与推理计算单元并非完全无竞争；不把“硬解分摊CPU”误写为一定减轻GPU压力。

## H5.0b DLL探测接线补充

后续r9已新增有序模型C入口与Python/C#封装，见[本轮记录](../verification/sdk-h5-ordered-selection-20261026.md)和ABI §3.2；下面H5.0b说明保留其历史边界。选择模型缓存8KiB、context最近尝试8KiB，纯读查询16KiB，默认control额度不足时拒绝而不扩额。context缓存随destroy释放，CLOSED查询只返回空状态，不把内部缓存当外部租约阻塞shutdown。硬件查询直接借用探测缓存并定容序列化，堆暂存按实际32KiB记账；一份设备缓存16KiB+context8KiB+单模型8KiB+硬件查询32KiB可同时在默认64KiB内。并发/更多模型仍可能明确resourceExhausted。

新增C显式probe/get_report及Python/C#便捷方法，合同见ABI正文H5.0b；报告只含设备缓存和累计观察，不含模型策略/原生Run细节。旧query_backends迁移、模型C允许列表及恢复继续待办。缓存16KiB内部控制额度、查询48KiB（32KiB定容序列化），默认总64KiB，不把内部缓存当未归还租约阻塞关闭。最大16个设备/每名称原始256字节的上界有单测，不构建JSON Value副本。
