## 2. 四个边界（2026-10-25 用户口径修正：交付主体=源码 SDK）

1. **核心能力独立**：相机接入、解码、推理执行与队列下沉到各自 crate。AM-RT 静态链接同源 Rust 核心；外部应用调用薄 C ABI。两者共享语义与测试数据，不维护第二套实现。
2. **源码 SDK 为交付主体**：交付物是**可脱离 AM-RT 仓库独立构建、复用的源码 SDK**（源码集=am-camera+am-vision+其内部纯函数依赖 crate（am-rules）+独立构建清单），Windows x64 DLL 只是编译产物之一。消费方式三种：源码集成（静态链接进宿主 Rust/其他绑定）、DLL C ABI 调用、后续平台产物。**不重写语言**（Rust 源码即交付物；C ABI 面向非 Rust 宿主）。
3. **接口稳定**：外部只接触版本化 C 类型、句柄、缓冲区和错误。Rust、FFmpeg、ONNX Runtime 的内部对象不外泄；C#/Python 包装只管理跨语言调用与所有权。
4. **平台依赖隔离与独立构建**：Windows 特定能力（DPAPI 凭据）已有 `cfg(windows)` 门控——SDK 化时收口为 feature（如 `credentials-win`）+非 Windows 提供明确降级实现（内存凭据/由调用方提供器承担持久化）；FFmpeg/onnxruntime 运行库定位支持显式目录参数（不依赖 AM-RT 的 vendor 相对路径约定，环境变量覆盖已存在）。**独立构建门（SDK-G0，新增验收）**：干净环境仅取 SDK 源码集（不含 AM-RT 其余代码/工作区配置），按 SDK 自带构建文档完成构建与单测；首版验收仍 Windows x64，其他平台支持范围单列为”首版设计、后续平台实施”（不默认宣称编译或运行已通过，不自动扩大首版承诺）。

独立不等于进程隔离：两个 DLL 仍在调用方进程内。Rust 可捕获的 unwind 应转错误；原生库访问违例、驱动崩溃不承诺由 DLL 完整恢复。

首版的“多消费者”指进程内受限订阅与连接复用，不是网络转发服务。ONVIF/海康私有 SDK/GB28181 均不由 ISAPI 接口隐含提供。

**共享帧池口径（SDK-DEC-07，逐字对齐终审 §11.1/§11.2）**：

- 共享内存=相机、推理两个 SDK 的**公共可选能力**，首版按上表交付；**不因此增加第三个 DLL**——公共实现为两个源码 SDK 共用的内部模块，复用代码与协议；分别编译进 DLL 不会自动形成共享运行时，共享段、资源拥有者和协议身份必须显式关联。
- “可选”指调用方可以不用此传输方式，**不是允许首版交付缺少该能力**：交付物须提供至少一种已验证的启用配置；其他裁剪构建可明确报告不支持，不冒充同等首版配置。未启用时保留普通内存输入输出。
- 每个对象由创建它的 SDK 入口释放；禁止把另一个 DLL 的本地句柄或指针当成通用跨进程句柄。
- 不由共享帧池承担：跨机器传输、断电不丢证据、录像/图片持久队列——共享内存是易失传输；报警证据和可靠存储沿用宿主独立链路。
- **共享内存≠零拷贝**：前处理、颜色转换、缩放和 GPU 上传可另需复制。GPU 互操作“后续”与共享内存“首版可选”并存不矛盾——**CPU 共享帧池首版可选启用，GPU 显存/硬件表面共享仍列后续**。
- 旧表述作废：不存在“共享内存一律后续”（CPU 帧池属首版可选启用），也不存在“同源自动共享”（共享段/拥有者/协议身份须显式关联，分别编译不自动形成共享运行时）。

## 4. 模型与前处理合同

- 兼容单位为「任务类型 + 导出档案」：输入输出名、dtype、shape、布局、颜色、数值范围、类别/关键点定义、NMS/端到端输出形式、坐标映射。不能仅按文件名猜 YOLO 版本。
- 图像入口由 DLL 完成解码、letterbox、颜色/布局变换、归一化，并返回变换元数据；调用方无需各写一套。张量入口默认不重复前处理。动态分辨率只在模型允许的范围内，不能擅自修改固定模型。
- Pose 需解出框与关键点；Detect 需兼容冻结档案的框格式及 NMS；Classify 需明确 logits/概率与 softmax 策略（不套用检测 e2e/NMS 二分）。Segment 的原型 mask 合成/裁切/缩放与 OBB 的角度单位/周期、旋转 NMS 同属首版五类范围（SDK-DEC-03），各自冻结档案并分别验收。
- “批量提交多张图”“ONNX 原生动态 batch”“自动攒批”分开报告。首版提供前两者的显式支持/拒绝；固定 batch>1 必须组成完整批次，尾项明确拒绝，不以单帧提交违反模型形状；自动攒批不默认引入等待延迟。
- 多模型句柄允许同帧供给不同模型；各自独立 requestId、版本和终态，受共享并发预算限制。融合判定、跨模型报警组合不进入推理 DLL。
- 模型文件路径为基础入口；内存模型入口纳入 6.1 冻结并写明大小/所有权。自定义算子、字符串、Sequence、任意插件加载不纳入首版数值张量承诺。

结构化结果使用 C 可布局数组/结构（框、关键点、类别分数）；原始张量附名称、dtype、维度、stride/连续性与拥有者句柄。JSON 仅用于低频配置和诊断，不传逐帧图像或大张量。

## 5. 生命周期、内存和错误

2026-10-26用户确认：底层ORT/FFmpeg运行库可常驻宿主进程，退出时统一回收；SDK自身对象、线程、回调与外持必须排空，双SDK模块仍须支持实际卸载/重载并验证预热后无持续资源增长。不得在DllMain阻塞回收或强卸载不拥有的依赖引用；同进程运行库路径/加速冲突仍明确拒绝，不能靠重载SDK切换。详见[冻结r5](dual-sdk-abi-freeze-v1.md#8-发布前原生运行库寿命修订r52026-10-26用户确认)。

- 采用 Context + 不透明子句柄；定义关闭顺序、同句柄并发许可、子对象存活规则。关闭须有明确完成屏障；超时返回“仍在关闭”，不能释放仍被工作线程使用的内存。
- 同步借用输入有效期到调用返回；异步默认复制，或显式 retain 一个受支持的拥有者。相机提供只读 CPU 像素视图，推理通过保留所有者或安全复制接收，调用方不需要 JPEG 编码后再解码。
- “DLL 分配，分配方 DLL 释放”；跨 DLL 只能使用已冻结的视图与 retain/release 协议，不能把 A 的指针交 B 的 free。图像需 width/height/format/plane/stride，不能假设所有行紧密排列。
- C# 用 SafeHandle，Python 用上下文管理器及持有拥有者的数组视图。默认提供易用复制模式；借用模式必须明确失效时机。释放后的访问不属于可支持的调用，但不能因正常 GC/包装释放顺序而悬空。
- 回调在 SDK 调度线程执行，不阻塞采集/推理；必须说明是否串行、允许的重入调用及返回前借用有效期。注销/关闭完成后不再回调；禁止回调内同步销毁自身造成死锁，提供异步关闭方式。
- 每个请求/对象返回错误码、UTF-8 消息、来源与可重试属性；不得仅用全局 lastError。异步错误可查询，错误回调仅通知。诊断不含凭据、完整含密码地址或默认输出原始图像。
- C ABI 使用固定宽度类型、明确调用约定、枚举值和 UTF-8；结构带 size/version，能力可查询，未知 ABI 明确拒绝。公开头文件从受控 FFI 声明生成或一致性校验，禁止导出 Rust Vec/String、OrtValue 或 FFmpeg 指针。
- 兼容小版本只增加可协商能力/尾部字段，不改已有字段顺序、枚举含义或释放函数；破坏兼容时提升 ABI 主版本并保留可区分的加载入口。消费者不能依赖 Rust 编译器版本维持 ABI。
- 调用方回调不得把语言异常抛入 C 边界；包装层捕获后转错误。同步超时、取消请求和工作实际停止分别描述，不能把“已请求取消”当成可立即释放在途内存。

同源静态链接可减少跨边界转换，但整体性能仍以解码、预处理、拷贝、推理和包装调用实测为准，不承诺全链路零拷贝。

## 6. 排队与资源限制

| 通道           | 满载/保留策略                                     | 调用方可观察结果                                       |
| -------------- | ------------------------------------------------- | ------------------------------------------------------ |
| 实时解码帧     | 有界丢旧留新                                      | 帧龄、序号缺口、丢弃计数                               |
| H.264 编码输出 | 丢弃后等待可解码关键帧和参数集，不能任意接回 P 帧 | 重同步事件、配置代次；禁止继续输出花屏链               |
| 实时推理请求   | 显式配置替换旧请求/过期策略                       | 已接受请求恰有一个终态：完成、失败、取消、过期或被替换 |
| 离线/批量请求  | 有界拒绝或带截止时间等待；不静默丢旧              | 未接受立即背压；已接受逐项可查询终态                   |
| 推理结果       | 固定预算、TTL/取走确认；结果持有也计费            | 待完成、已完成、已过期可区分；预算不足限制新接收       |
| 控制/错误通知  | 独立预算；可合并状态但保留可查询真相              | 数据队列满仍可取消、关闭、读故障；终态不靠易丢通知维持 |

限制同时覆盖项数、字节、源数、模型数、并行数、等待时间及外部尚未释放缓冲区。慢订阅者只阻塞自己的预算；同源复用必须包含凭据/权限隔离，不能跨调用方泄露流。推拉使用独立订阅游标或明确互斥，不隐式竞争同一条数据。

相机/推理核心与 AM-RT 使用同一预算，不能宿主排一次、DLL 再排一次形成双重积压。提供资源耗尽、队列深度、丢弃、帧龄、耗时分段与实际后端统计即可，不引入通用作业平台。

## 7. 视频合同与恢复

- 编码包注明 packet/访问单元边界、Annex B/AVCC、SPS/PPS、关键帧、PTS/DTS/时间基、配置代次。MJPEG 标明真实编码，不伪装 H.264；首版不做通用转码器。
- 抓图接收时间、设备采集时间（确实可得时）、RTSP PTS 不可混为同一时钟；输出时间来源与映射质量。断线、重连、码流/分辨率变化后递增源代次，旧检测/叠层失效。
- 检测 5 FPS 不等于只读取或解码任意五个 H.264 包；先维持参考帧依赖，再从已解码帧按节拍取样。缩放按需求生成，不默认每档都分配。
- 归一化 ROI 仅在视场、裁切和方向一致时可直接跨分辨率使用。变化须给变换或要求重确认；PTZ 后的视场变化不得悄悄沿用原 ROI。
- 重连内建指数退避、抖动和上限，开放超时/重试/取消参数；不能无限阻塞关闭。探测结果带有效期、刷新与凭据版本失效机制，区分超时、认证失败和不支持。
- 凭据直接注入或由调用方提供器刷新，DLL 不持久化。DPAPI、相机档案和三流地址生成政策留宿主；其他品牌不保证恰有三条固定地址。
- **独立解码入口（N01/SDK-DEC-02）**：已取得标准 H.264/H.265 压缩数据的调用方直接创建解码器提交访问单元（创建→提交→零/一/多帧输出→drain/reset→关闭屏障→释放），不重连相机；封装/参数集（含 H.265 VPS）与随机访问语义按档案声明，厂商私有混合流明确拒绝。软件解码与冻结硬件矩阵分别验证。
- **ISAPI 连续取图（N02/SDK-DEC-04）**：SDK 负责定时、限速、恢复与缓冲，复用单次抓图的凭据与状态通道；采样上限内错过跳过不补发，实际取图频率/帧龄可查，过期图不刷新时间冒充新图；连续图片不是视频流，不隐含编码器或录像能力。

## 8. 接口优先矩阵

以下为 6.1 冻结时必须逐格确认的范围；每个格需标注支持/明确拒绝/后续，不能只提供一个通用 JSON 接口。

| -------------- | ---------------------------------------- | ----------------------------------------- | ------------------------------------------ |

| P0             | RTSP + 取帧/缩放需求                     | CPU 像素视图、帧元数据                    | 异步推/拉，同源受限复用                    |
| P0             | 独立压缩数据（H.264/H.265 访问单元/包）  | 解码帧、帧身份与时间元数据                | 无网络源；drain/reset/关闭屏障（N01）      |
| P0             | ISAPI 地址/设备引用 + 凭据               | 编码图片或 CPU 帧                         | 单次同步/异步抓图（超时可取消）+ 连续订阅（采样上限/错过跳过/实际频率可查，N02） |

## 9. 四个验收门（SDK-G0～G3）的独立验收

所有项目当前均为**待实施、待验证**。每项证据记录源码提交、头文件/ABI 版本、包摘要、环境及实测结果；不从设计或模拟结果推导硬件通过。每门的**实现单测、文档校验、硬件验收、用户签收分别记录**，缺项标待办，不互相代替也不代签。

| 门                  | 必验场景                                                                                                                          | 通过条件与证据                                                                                                                                                               |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SDK-G0 独立构建     | 不含主仓的干净目录，仅取 SDK 源码集与构建材料（manifest/lockfile/feature/测试资源）                                               | 构建成功并运行自带测试；完整依赖闭包不靠父目录或工作区继承解析（B15）                                                                                                        |
| SDK-G1 核心独立     | 干净目录中的外部 C#/Python 示例，仅部署 SDK 包；不启动 am-server、AM-RT worker，不提供业务库/配置/UI；跨进程共享帧启用配置下完成发布→借用→推理→归还（SDK-DEC-07） | 可完成抓图/取帧→同一只读 CPU 帧推理→取结果→释放；Rust 宿主直连同核心对同样本结果等价；诊断/队列/多句柄无需 app-core 服务；共享帧路径不依赖 AM-RT 服务                          |
| SDK-G2 ABI 与所有权 | C/C++ 编译公开头文件并实际调用；C# SafeHandle/Python 数组视图；UTF-8 路径；回调注销/销毁竞态、在途取消、过期、队列满、提前 GC、模型代次切换；共享帧借用/归还/消费者退出与进程重启、旧代次归还竞态（SDK-DEC-07） | 已接受请求单终态；有效保留对象不悬空；关闭屏障后无回调；异常输入可诊断；旧消费者加载兼容小版本正常，未知 ABI 明确拒绝。重复关闭/无效句柄按约定处理，不依赖触碰任意悬空裸指针 |

附加负载验收：受控慢消费者、断流重连、持有缓冲区达到上限、持续取消/重建模型后，内存与线程/句柄数量保持在冻结预算内；记录实际峰值和恢复结果，不要求人为制造原生越界来证明“崩溃可恢复”。

**共享帧池验收（SDK-DEC-07，按终审 §11.4 验收清单）**：首版验收至少覆盖——跨进程单路多模型及多个源的**帧身份隔离**、慢消费者与满池、持帧不覆盖、取消/关闭、消费者退出与进程重启、分辨率超限及旧代次归还。记录字节/槽位/等待上限、错误、资源回落和实际复制边界；C/C++、C#、Python 分别提供可运行入口，不能只以文档或 import 成功代验。

补充入口级验收：ISAPI/外部像素发布、共享帧转既有像素输入、异步提交接受后立即return仍安全、NV12色彩与PTS时间基、多源发布ID不覆盖原帧ID、活读者失联不复用、关闭屏障、多池累计预算、协议/非法平面拒绝，按共享帧合同 §6 留证。

交付包包含双 DLL、公开头文件、C#/Python 示例、模型档案与支持矩阵、运行库/构建选项/许可证、版本摘要和诊断说明。Java JNI/JNA 可后续封装；首版不以“理论能调用”冒充 Java 已验收。

GPU 硬件探测、provider 库存在、provider 成功加载、模型实际在该 provider 执行分别报告；不能仅凭显卡名称声明 CUDA/OpenVINO 路径通过。

2026-10-26 用户澄清：干净环境指不借用主仓、开发工具或隐藏依赖；允许已安装兼容 VC++，有显卡的电脑同样可验证不依赖 GPU 加速库的 CPU 包。不为验收卸载运行库或禁用显卡；重点是依赖齐全可运行，缺失/不兼容/能力不可用有明确错误信息。SDK 自身无法装载时由调用方加载层提示，不能要求尚未装载的 SDK 返回错误。第二台 Windows 实证与实际诊断缺口 (historical host reference, not included: `../verification/verification-dual-sdk-remote-20261026.md`)分别登记。
