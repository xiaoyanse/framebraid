# R3 来源临时快照容量收口（2026-10-27）

## 范围与验收口径

只调整 Media 来源事件及队列统计的临时快照。C ABI、源身份/reuse、默认额度、事件队列策略不变；不修改 AM-RT，不连接现场设备。按 MET-2 以可证明固定存储和去除快照堆分配为主目标，成员完整性、锁序、关闭安全及最坏处理成本为保护指标；不以硬解与 CPU 速度互比或完整硬件矩阵/固定长跑作为门槛。

## 实现与取舍

- 原事件路径在共享源锁内 collect Vec；原统计路径在全域登记锁内建 HashMap，再 collect Vec。现在锁内仅将当次全部对象升级/克隆到安全固定强引用数组，锁外通知或访问 Hub；不采用分块遍历，避免关闭/新增导致成员漏读或重复。
- 上界直接取原域 SDK_MAX_REGISTERED_HANDLES=4096。x64 的 Option<Arc<T>> 为8字节，数组32768字节，含长度的 Snapshot 为32776字节；每调用占独立栈空间，无常驻缓存、TLS、unsafe 或快照分配失败路径。不把栈占用记成零成本，也不把类型大小当完整调用栈峰值。
- 统计先完整收录所有别名对应的共享源，释放登记锁后按单调唯一 source_id 原地 sort_unstable 并去重，最坏 O(n log n)，无每项扫描的 O(n²) 去重。同源多别名计一次，同URL但独立源仍分别计数。
- 事件发送仍检查 closing，已有关闭过滤不变；events.push 只入有界提示队列，不在当前调用内执行外部回调。快照保留当次对象到遍历结束，新增成员不混入；并发关闭可以更新状态，快照并不冻结对象的可变内容。
- 小栈测试使用明确512KiB线程，不探底。现有 SDK 工作线程由 std::thread::Builder 默认栈启动，未新增更小栈设置；调用方任意小栈/任意并发线程数量不在本次证明中。每并发调用独立承担固定栈成本，不宣称全进程RSS硬上限。

## 定向验证与量化

新增三项测试：4096槽全成员及捕获/原地排序访问零堆分配；512KiB线程上的构造/传递/排序/释放与4096唯一项40轮微基准；真实 Source/SharedSource 对象的同源别名去重、独立身份、锁外访问、并发关闭强引用及新成员隔离。

微基准只比较固定快照+排序与旧 HashMap+Vec 的容器处理，均不启用分配计数器计时；旧路径单轮分配另行计数。它不包含相机网络、Hub锁等待或队列数据计算，不能推广为实时视频/总体吞吐提升。实际 Debug/Release 由主代理统一编译运行，结果见下。
