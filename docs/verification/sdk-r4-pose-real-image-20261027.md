# R4 Pose 非空结果复制验证

基线为 main 的 `c90d452`；验证在 Windows x64、本机 CPU 和开发构建 DLL 上进行。使用 Ultralytics 安装包附带的 bus.jpg（SHA-256 `c02019c4979c191eb739ddd944445ef408dad5679acab6fd520ef9d434bfbc63`）和 YOLO26n Pose 模型（SHA-256 `80fb5f58a3f6ec18909427ecc74fec0910196c2d2e924659eaae6dea5857b957`）。DLL SHA-256 `49ebd1bfe28f9ee1c4e92a417b7f15f72d11a5d62fefcbda67c286106c6c53be`，并非正式发布产物。

Python 和 C# 分别运行真实图片推理，均得到 4 个 Pose 检测；两边分别将复制后的框、置信度和关键点与各自原生结果逐项比较，并验证应答、释放及垃圾回收后副本仍可读取。原有合成数据、无效输入和关闭竞争测试通过；Python 空白图 CPU 结果为 0。

补充后处理参考对拍：Python 从同次推理复制 `output0` 原始张量（1×300×57），独立按档案计算 letterbox 逆映射、阈值和关键点，逐项比较结构化结果，容差 1e-5，4 个检测通过。这检查张量到结果的转换；参考输入仍是 SDK 推理得到的张量，因此不证明前处理或推理引擎独立一致性。

补充独立运行对拍：`scripts/sdk/test-pose-independent-ort.py` 对同一 RGB 输入由 NumPy 独立实现档案前处理，Python ONNX Runtime 1.27.0 CPU 运行同一模型，比较 SDK 原始输出的有效检测（置信度 ≥ 0.25，4 项、按原顺序），`rtol=atol=0.001` 通过；有效行最大绝对差 `0.00006103515625`，P99 `0.000030517578125`。全部 300 行按索引比较最大差 `520.445068359375`，主要不在有效检测行；低分候选的差异原因未完全确认，不声称全张量一致。SDK 所用运行库 SHA-256 `66e62f7bebf65b048ff1a93c40a73df93c36f93ce5bb085076de92b1a1e754fd`。此测试使用相同 RGB 像素，不覆盖两端各自的 JPEG 解码差异。

这是单样本、单 CPU、限定档案的复制、生命周期、后处理和独立运行对拍，不是两语言输出的直接逐项对拍，也不证明检测准确率或其他模型类型。R4 的五类模型及参考对拍要求仍待完成，不以本次结果关闭。
