## 1. 发现的评价问题与修订

| 问题 | 原评价容易造成的误解 | MET-2处理 |
| --- | --- | --- |
| 把不同目标都评成耗时下降 | 硬解、缓冲复用、语言接入、故障恢复都必须更快 | 每包一个主目标、可选次目标，分别选资源卸载、机制成本、等待/公平性、正确可用或恢复 |
| 跨后端与同路径混比 | 硬解RGBA慢于CPU就算缺陷 | 跨后端评资源取舍；同路径优化才评改造收益/回归，两者都保护场景硬预算 |
| 统一5%线 | 1ms轮询测试约0.06ms变化与生产严重退化等价 | 历史事件保留；测前用A/A、绝对/相对实际影响及硬预算判定，不自动失败或通过 |
| 机制计数外推资源收益 | 转换次数减少83%就等于CPU占用下降83% | 机制、局部耗时、进程CPU时间、承载及整链各自给证据 |
| 合成预算外推SLA | 旧20/50/100ms适用于所有相机/模型/应用 | 继续按原工具负载保存，新场景填写需求/预算来源；未明确实际目标时只能报实测包络 |
| 合成/局部替代组合负载 | 单IDR、Identity或虚拟时钟证明实时网络/真模型能力 | S0～S6按任务选择真实GOP、模型和组合场景；不做无意义全组合穷举 |
| 分母不充分 | 少收/少交帧、批次均摊或计时外搬运制造提速 | 各级计数、期初/期末在途、唯一有效交付及完整计时边界对账 |
| 路线状态过时 | R2表格写未开工，但后文已经有硬解/采样交付 | 当前阶段表按已保存的实际成果修订；H2/H5、R3/R4和长跑未完成项保留 |

修订不是降低安全标准：帧/请求关联、模型精度合同、队列/内存/线程硬限、活租约、唯一终态和关闭安全继续独立作为底线。硬预算被违反不能用“波动”“CPU节省”抵销。

## 3. 需要继续保留的缺口

- **H2-STREAM-01**：补CPU时间、GPU相关引擎/显存、有效交付及并发包络，才可评价硬解是否实现资源目标；现有跨后端耗时不被抹去。
- **H2-STREAM-02**：同读流线程同步解码/回读可能影响压缩消费者，仍需有界隔离与预算内服务验证；不得因改指标关闭。
- **R2-SAMPLE-01**：真实时间抖动下采样可能低于标称配置，虚拟时钟不代真实输入节拍。
- **R2-SAMPLE-02、H5-CORE-PERF-01**：同路径历史警戒待A/A与绝对影响审查，未证明确实回归，也未证无回归。
- **跨硬件像素/模型容差**：按颜色/布局/模型档案预先定义，再检验不同转换路径；没有依据不许放宽，也不能把算法不变的同路径字节校验删掉。
- **H5及路线余项**：模型C允许列表、真实CUDA/OpenVINO可用性、运行期恢复、张量/语言热路径、自适应组批、组合故障和4h/24h未被这次文档更新完成。
- **MET-2工具前置**：现有工具仍按旧JSON/预算/5%标签工作，CPU时间/GPU引擎、A/A与新场景未全面接入；恢复开发后按R1 M1.1/M1.2补必要部分，不一次建设监控平台。

## 4. 排期及目标卡

本次M0只完成评价体系与文档；不启动任何性能测试。恢复实施前先做下一包的最小量化前置：

1. H2选S1/S2及必要S4，固定同等输出/采样和宿主预算，主评CPU卸载或合格路数，保护帧龄、其他消费者和资源；先补实际CPU/GPU及A/A测量。
2. H5选S3及必要S5，主评允许策略/真实模型可用和失败收口；调度再选S4看等待/过期/公平性或离线吞吐，不要求GPU默认更快。
3. R2后续热路径按机制热点继续；R3/R4及R5后续依赖、4h/24h要求保留。固定同一稳定候选可复用一次长跑证据，不每次提交重跑整包。

目标卡及字典见MET-2第3～6节。CPU节省比例、最大路数、具体场景帧龄/容差在测前有依据地标定；当前没有数据的值明确待标定，不写虚假的百分比或SLA。这不削弱现有接口硬限和已确定的功能断言。
