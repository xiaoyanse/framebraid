# MET-2 M1 / S1 量化目标卡

状态：**测前固定，尚无结果**。测量工具归 R1-M1，硬解资源取舍归 R2-H2；不是新的公开能力或发布验收。源码基线 `8d8a1f1`，原 SDK 代码仍为 `088f821`，使用现有 Release Media DLL，以运行时 notes 与制品 SHA 为准。

| 项目 | 测前约定 |
| --- | --- |
| 本轮主目标 | 建立可信的进程 CPU-s / 固定窗口和有效交付分母，完成同实现 A/A 与 CPU/硬解资源对照；本轮不改解码实现、不承诺节省比例 |
| 场景 | S1 单路，离线自产 H.264 MP4，1080p30、yuv420p、2 个 B 帧、GOP30、参数集随关键帧重复；DTS 定拍，不是现场 RTSP 或显示端 |
| 入口与输出 | 同一 Media DLL、相同 FFmpeg、同一输入 SHA；CPU 与 PreferHardware 分别实调 C ABI 解码、CPU RGBA8 全尺寸输出并及时归还；必须核实际后端，硬解静默回软解视本组控制无效 |
| 身份/准备 | ffmpeg/ffprobe仅备料与封装解析；AU与ctypes输入在计时前准备，SDK提交至收到像素视图/元数据为响应边界，含参考帧重排；不含浏览器、网络、相机曝光或完整RGBA复制 |
| 固定窗口 | 每轮预热2秒，稳态6秒，每种策略3轮交替顺序；各策略另做1轮观察关闭控制；总实测上限12轮/3分钟，不为变绿反复追加；首次工具校验可做2秒短烟测但不并入基线 |
| 计数与正确性底线 | 期初在途+窗口输入=窗口全部输出+期末在途；测量输入窗口内/外交付分列；排空不得丢帧/重复PTS/代次变动，尺寸格式正确；像素数值/真实模型精度不在本包验收 |
| 实验保护线 | 新鲜度200ms、窗口内有效交付至少预期180帧的95%（171帧），窗口时长误差≤100ms；仅本次自产单路实验要求，不是产品SLA。内存/队列沿用SDK硬限，不因测量放宽；原生调用异常停止本轮并保留失败 |
| A/A与有意义差异 | 报每组CPU-s、响应P95、有效交付的最大最小值/绝对及相对跨度，不事后选最快轮。CPU取舍的调查门为至少0.1 CPU-s/6秒且10%，延迟为2ms且10%，并须超A/A跨度；这是分辨/复核门，不是自动性能通过线；若波动覆盖差异则证据不足 |
| 资源采样 | Python进程CPU含调用方、SDK、FFmpeg和采样线程；CPU-s/墙钟、核心等效及可用逻辑并行度归一比例；PDH英文GPU Engine/Process Memory计数每250ms，按PID/LUID/引擎保留，不求各引擎和。缺实例/失败记未知，最多4096采样，不写热路径磁盘 |
| 观察开销 | 报采样线程CPU含初始化/关闭，并以关闭控制观察总体CPU和响应变化；控制仅一轮为开销调查，不可作为精确可减成本。缺GPU观测不填0；采样内存峰值不是绝对峰值 |
| 证据位置 | 新目录 `.local/evidence/met2-s1-20261026-*`，备料 `.local/tests/met2-s1`；原数据和旧5%标签不覆盖 |
| 本轮结论边界 | 工具正确/生命周期、同实现重复性、跨后端资源取舍分别结论；没有S2/S4混合消费/推理竞争、多路、长跑或像素容差，不宣布整体硬解性能完成 |

依据：[MET-2](../PERFORMANCE_ACCEPTANCE.md)、[R1任务](../../openspec/changes/sdk-r1-performance-baseline/tasks.md)。结果另建验证记录，不回填测前门槛。
