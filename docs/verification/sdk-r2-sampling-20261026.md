# R2 1.2 采样前移局部验证（2026-10-26）

> **当前评价依据：MET-2。** 下文保留当时原文、数值与判断；新口径见文末补充及[统一复核](sdk-metrics-review-20261026.md)。本次未重新运行测试，不能把口径修订当新增验收通过。


基线`35985a8`。Windows x64 Release、真实FFmpeg CPU解码、生产Hub.emit_decoded/pixels.fanout和独立资源域，合成1920×1080 H.264；调度时钟为虚拟30 FPS，不是实时网络流。未启动前后端/测试服务器，不连接设备，不改AM-RT。

## 改动

订阅新增无副作用`needs_pixels(now)`，与`due`共用资格检查；无回调、停止或回调更换中不请求转换。前者不更新last_frame，fanout才推进实际采样机会。H.264/HEVC仍送包、接收并丢弃未到期帧，FFmpeg继续维护参考链，不按推理FPS跳过压缩包。尺寸在转换前观察，未到期帧仍更新健康时间；需要输出却预算失败时不先发“恢复正常”而导致资源错误来回闪烁。

源内seq仍随解码帧推进，不能因跳过转换而将采样输出错误改成连续seq；原生验证同时对拍PTS、received和seq。全局frame_id仅承诺唯一身份，不承诺不同测试轮次相同数值。

MJPEG在读取/校验尺寸头之后检查需求，未到期跳过完整图像解码；原始压缩广播路径保持在像素路径之前，纯编码消费者仍不启动解码器。该分支本轮仅代码接线，实测矩阵保留开放。Hub原文件接近800行，按consume职责拆到子模块，不通过压行数隐藏规模。

C ABI、布局、生成物、队列和max_fps语义均未改；测试时钟/隔离源构造只在cfg(test)存在，不给宿主增加配置负担。生产仅实例化启用前移的emit；关闭前移的泛型分支仅供测试进行“每帧转换”消融对照，不是历史二进制比较。

## 可重复量化

显式环境变量`AM_RT_FFMPEG_DIR`和`AM_SDK_H264_SAMPLE`后运行：

```powershell
cargo test --release -p am-camera-ffi --features shared-frames native_sampling -- --ignored --nocapture
```

每组先20帧预热，再90帧；三轮消融对照。实际native sws_scale函数指针仅在测试API副本计数并转发，未修改运行库。计时为send+生产emit/fanout，不含消费者pull和完整平面指纹；90个逐帧样本计算nearest-rank P95，不宣称P99。所有路径仍解码90帧，输出数量、PTS/received和全RGBA平面64位指纹逐项匹配对照，域额度关闭后均归零。

## 发现与未验

- **R2-HW-01**：RTSP源/订阅没有hw_policy合同，需要兼容新增策略和快照入口；不得借用reserved或私套独立decoder配置。已登记R2设计，H2.1/H2.3与H5继续优先。采样优化不冒充自动硬解完成。
- **R2-SAMPLE-01**：保留既有严格最短间隔采样策略。输入时间抖动时可能低于标称FPS，需真实网络量化后再决定是否使用有界令牌/截止时间调度，不能用理想虚拟时钟掩盖该风险；同步R3。
- **R2-SAMPLE-02**：混合满帧需求P95告警尚未解释/消除；本提交为功能及量化保存检查点，不是优化完成验收。继续检查转换/分配/锁开销和真实负载，保留原告警证据。
- 真实RTSP时序/抖动、P/B帧网络参考链、HEVC/MJPEG、动态尺寸与关闭竞争未完成，因此R2 1.2不勾选。未运行长跑，不把当前零域额度视为驱动/生产内存稳定证明。
- 自查正确性、资源寿命、采样资格、凭据和性能边界，无新增阻断；将健康通知前置到预算失败之前会造成状态翻转，已在收口前改为只对未到期丢帧更新健康，预算错误保持原报告行为。外部.gitignore变更保留、不提交。
