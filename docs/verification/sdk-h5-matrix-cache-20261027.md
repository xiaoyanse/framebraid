# H5 旧 C 后端矩阵的显式探测缓存（2026-10-27）

基线 `e8af497`。旧 `amv_query_backends` 先前每次调用 CUDA 初始化，可能被驱动阻塞且无法区分未知/无设备。现在 C 入口读取同 context 的显式探测缓存，不主动进入 CUDA 驱动；未探测、刷新中或失败且设备数未知时 hw_detected=0，note 明示 unknown；探测得0与大于0分别表示已确认无设备及可见设备。探测新一轮撤销旧缓存，不能用过期的成功报告冒充当前状态。依赖、provider 和真实推理字段仍分别报告，不将显卡可见解释为可推理。

**迁移注意：**旧 C 调用方如依赖一次矩阵查询立即触发 CUDA 检测，需先显式调用 `amv_probe_inference_hardware`，再查询矩阵或详细报告。C ABI 布局、导出和值域不变，但这是调用行为变化；同版本文档/绑定/库需匹配。Rust 公开 `runtime::query` 保留历史主动探测行为，新增 `query_snapshot` 才是无驱动查询，因此 H5 整体并未关闭。

验证：Vision 核心及 FFI 定向测试与严格 clippy、Release DLL 构建通过；单元覆盖未探测/失败/无设备/存在区分、probe busy 时不等待被占用的缓存锁。本机 C ABI 通过 Python ctypes 验证：前置 unknown、probe 后与实际结果一致、50次矩阵结果稳定、控制预算失败后缓存撤销、关闭与查询并发；100次详细报告查询 P50 0.01285ms/P95 0.0299ms（每次三次C调用+JSON解析，非矩阵耗时对比）。本机驱动 `cuInit` 返回100，设备数量未知，不能据此声称CUDA模型成功；同 DLL 测试CPU模型加载/真实推理、缺失/损坏运行库恢复、共享帧无ORT及外部运行库冲突通过。
