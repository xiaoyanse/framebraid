# R3模型读取上限与同候选收口（2026-10-27）

评审基线 `b50e3e9740e8e94637c43ae401d0bf4f2463ac2a`，Windows x64、all-features、SDK main；未改AM-RT、未推送或发布。目标：模型预检查的SDK拥有缓冲不能因文件检查后增长而越过256 MiB；内存输入在同步加载时避免重复拷贝。保护正常文件/内存加载、已有限额错误、失败后模型名额及原生执行正确性。

## 变更与边界

- 文件入口先打开一个文件句柄，从该句柄读尺寸；大于256 MiB先返回 `vision.modelTooLarge`。按该长度fallible预留、检查实际capacity，再读精确长度并检查额外1字节，不使用可继续增长的 `fs::read`。分配失败返回 `sdk.resourceExhausted`。文件在读取期间缩短或增长时返回 `vision.modelLoadFailed`；已达256 MiB后仍有额外字节返回 `vision.modelTooLarge`。旧版本会先读取增长后的文件，再检查是否超限。
- 内存入口同步借用调用方字节，校验和ORT会话创建完成后返回，不再构造第二份SDK模型字节Vec；调用方在调用返回前必须保持缓冲有效且不修改。常规 `commit_from_memory` 已用于现有接口，不启用需要长期持有输入的 `commit_from_memory_directly`。这不等于ORT内部或输入端到端零拷贝。
- 以上上限针对SDK预检查副本，不是进程总内存上限：路径加载在8 Context×每Context最多8模型的理论极限下最多64个各256 MiB副本，受实际并发/释放时序影响；调用方内存、ORT会话、外部权重、驱动及系统缓存另计。应用应控制同时加载数量与宿主资源。
- **仍有路径一致性边界：** 为兼容外部权重，现有ORT路径入口在SDK检查后会再次按路径打开模型；如果其他进程在加载期间替换文件或外部权重，SDK不能保证ORT实际读取的内容就是已检查版本，也不能限制ORT内部读取规模。调用方须在整个加载期间保证模型和相关外部权重稳定可信；多平台不可变快照/外部权重约束是后续安全加固项，本次不宣称已经解决。内存输入不支持ONNX外部数据的限制不变。

## 定向验证与量化

原始结果在 `.local/evidence/r3-model-read-20261027/`，二进制与模型身份在 `identity.json`。测试输入均为本地隔离样本，未触碰现场。

- Cursor确定性模拟文件增长/缩短、超限先拒绝且不读输入、可调小上限下正好满额和再多1字节；内存输入保留相同指针和内容。新增3项均通过。
- Release局部复制对照：8 MiB输入×20次，旧内存副本20次分配，新借用0次；单轮旧47300µs，新低于计时分辨率。只覆盖SDK本段，不把该差值称为完整加载或推理加速。
- 文件热缓存对照：同一个12125864B ONNX，三轮各20次，旧 `metadata+fs::read` 为106435/89205/97428µs，新 `open+metadata+预留/初始化+read_exact+额外字节检查` 为107078/108526/115184µs；每轮交错、未含ORT。新路径均值约5.51ms/次、旧约4.88ms/次，存在约0.63ms/次的观测代价；三轮是有限局部样本，不作为跨机器或整体加载结论。新路径初始化缓冲后读入，是性能换取受控内存边界的取舍。
- 实际Vision DLL使用CPU Identity：C#/Python的同步/异步、fetch/ack及共享租约通过；有序选择对路径和内存均运行成功，内存入口返回后覆盖原缓冲再推理仍正确；CPU版环境下严格拒绝缺失provider并允许CPU回退。
- 连续20次无效模型加载返回1000并且未发布句柄，随后正常模型加载及CPU推理成功，验证模型名额/线程许可可恢复。首次语言脚本把相对路径传作输出，被工具的绝对路径校验拒绝；改用原工具要求的绝对 `.local/tests` 路径后通过，未放宽检查。
