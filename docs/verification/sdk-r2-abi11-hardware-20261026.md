# R2 ABI 1.1探测与快照扩展验证（2026-10-26）

> **当前评价依据：MET-2。** 下文保留当时原文、数值与判断；新口径见文末补充及[统一复核](sdk-metrics-review-20261026.md)。本次未重新运行测试，不能把口径修订当新增验收通过。


基线`c4777a0`，FrameBraid main，本地Windows x64 Release。仅合成输入和本机显卡，不连接相机、不修改AM-RT、不推送/发布。合同见dual-dll-abi.md §1.1扩展；这是完整可回退的首组兼容接口，不是H2/H5整组验收。

## 兼容与边界

- 新增2个Media导出，总函数123；结构74个、字段偏移547不变。两库共享ABI 1.1，运行时版本从实际常量派生；新实现接受1.0/1.1初始化，拒绝不同主版本或更高次版本。
- 旧1.0 freeze原字节复制到sdk/abi/history/freeze-v1-r5.json；逐一核对其8个工件与基线Git原字节相同。原1.0冻结正文/模型档案/布局不改，当前新链引用旧SHA，含1.1依据及最低JSON字段约束，共9个冻结工件。
- probe有限初始化后释放设备/codec，不读取目标码流；快照不创建原生会话，不自动刷新缓存。query复制到调用方缓冲，NUL终止；长度探测、短缓冲、重叠输出和64KiB上限有合同。
  - probe找到首个初始化成功候选即止，attempts不是全量显卡清单；完整源/设备选择任务保持开放。
- 同context探测独占，重叠tryAgain；不同context共用既有底层有限选择准入。缓存每context一份，预留后按实际capacity收缩；query序列化先取得控制额度。缓存不持有Context强引用，关闭/销毁无环。
- decoder的初始化报告用Arc共享，帧热路径仅更新已有小型状态，不每帧序列化JSON。真实执行、配置代次、原生失败及最近实际后端分别保存；reset清除旧失败，关闭后仍可读最后观察值，不表示设备仍活着。
