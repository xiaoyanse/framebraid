## 实现与边界

- CPU目标回读从隐式FFmpeg transfer pool改为显式目标帧；按NV12/P010LE、32行/64字节对齐和512字节填充计算保守预算，再核实际AVBufferRef大小。格式列表、错误残留缓冲均由匹配运行库释放。
- Rust提供作用域回读和最多一张缓存的复用回读。作用域模式所有退出路径释放CPU暂存；复用模式必须让预算许可覆盖缓存寿命。硬件原帧/PTS在预算不足和回读失败时仍可重试。
- 直接解码与RTSP像素复制共用`BudgetedDecoder`，缓存持有期间保留Context Charge，格式/大小变化先释放旧缓存和旧许可，再准入新缓存；错误、丢弃和关闭归还。输出Vec独立，不因下一帧覆写。真实硬件组件测试覆盖额度不足→归还额度→同帧重试→保留缓存额度→不同画面复用→清缓存后归零。
- SwsContext按输入格式/输出格式/尺寸键控，每解码器最多一个；切换重建、错误失效、销毁释放。算法和flags不变，未以改变像素换取性能。
- 默认C ABI仍走原CPU入口；自动选择/诊断/运行期恢复尚未接入，不能把上述组件验证标为DLL/RTSP整链硬解通过。驱动与DPB内存仍为原生观测，未承诺硬限或GPU零拷贝。

合同：[原生硬件](../design/native-hardware.md)。H2.1～H2.4、R2其他热路径与长跑、H5等继续。

## 量化与告警处理

输入、运行库、线程预算不变，200个测量帧+20预热，每组全部交付且同后端前后输出校验一致。计时仅copy_rgba，解码和输出hash在外；GPU计时包含CPU回读，不是视频端到端FPS。新工具增加实际后端/LUID与transfer/scale分段观测，不把硬件偏好当实际路径。

1. 上一实现固定220帧创建/释放SwsContext各220次，本候选各1次。只说明机制次数下降，不冒充CPU负载同比下降。
2. 初版逐帧释放回读缓冲的GPU P95增加8.55%/10.26%/9.15%，触发警戒，未直接接受。改为有预算的单缓冲复用，并纳入SwsContext复用。
3. 跨时段比较仍出现CPU/GPU告警，保留原结果；分段显示颜色转换耗时亦有明显波动，尚不能据此断言软件或硬件根因。
4. 同一对已核SHA的制品交替三组，GPU P95变化+3.48%/-9.68%/+1.06%，CPU为-7.69%/+4.42%/+0.60%；六组均未触发既定P95/有效交付率/吞吐警戒，checksum一致。记录在`h2-readback-paired-20261026`与`h2-readback-cpu-paired-20261026`，不删除初期告警。

此阶段接受缓存/预算机制与本地定向回归，不宣称普遍提速，也不把交替短测替代H2.4的码流矩阵、CPU/显存观测、端到端测试和R2 4小时/R5 24小时长跑。P99仅200样本，不标代表性通过。
