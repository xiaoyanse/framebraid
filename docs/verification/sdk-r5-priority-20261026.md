## 改动与不变量

旧执行器只取“不忙”模型的请求，忙模型后面已取消/替换的排队输入仍占全局额度。
现在可运行工作仍优先，空闲线程独立清理这些未执行输入；不等待同模型活请求结束。
只在取消/替换/关闭后触发额外扫描，普通高频提交不增加records扫描。
释放在域锁外，try_lock避免与准入的records→域锁反转，唤醒与wait使用域锁握手。
清理不改另一项的busy/running；原生批次有有效项、实际读取未结束时，仍保留整批输入。

未新增ABI、批次模式、线程或宿主依赖；原提取清单/8件冻结不改，四个核心文件通过来源覆盖清单登记。
源码恢复A/B逐字节核验，当前保留候选；外部`.gitignore`不纳入提交。

实际Windows x64 CPU DLL，同一ORT和模型。域预算2 worker、8槽、总线程16。
先确认忙模型首项RUNNING，再排7项并取消/替换，健康模型尝试进入。
