# R3 全路径预算审计矩阵

本表是R3 1.1的核查入口，不是整包通过证明。当前源码评审起点`3e0898a77d7996d16ebcfb5b04d991dbea839fe6`，本次另包含媒体抓图表存储修复；每条运行证据仍绑定原记录的具体提交/DLL，不把历史短测冒充当前候选全量重跑。当前未关闭项见最后一节，父任务1.1保持未勾选。

## 核查口径

- 分开载荷、容器容量、配置/暂存、外部引用、共享映射、回调和线程。共享Arc载荷不因多个队列引用重复算物理字节，但各引用槽本身仍须有容量与额度依据。
- 分配前准入，空闲但仍分配的容量持续计费；停止/取消不等同真正释放，原生在读或外持租约不能提前退账。新旧重建重叠资源均计入。
- 数量有界不自动证明字节计费完整；len、capacity、底层分配请求、RSS不能混用。allocator额外开销、驱动/FFmpeg/ORT内部内存另列，不把SDK额度冒充进程硬限。
- “限定已验”只覆盖列出的对象/失败/负载，长跑与完整硬件矩阵分别验收。公开scope、线程/原生内存等字段存在不等于实现已完整填报。

1. **BP10**：补完通用Context服务、域对象/拥有者注册及其他服务索引的保留容量核查；执行器/推理请求/媒体抓图系列索引由1.1l/m/n完成，首轮分配/扩容前有额度依据，空闲容量不退空账。受理前拒绝不发布ID；已接受请求的后续失败须终态收口，不能混同。重放相关拒绝/TTL/关闭与小控制额度用例，记录开销及任何准入变化。
2. **BP12**：补真实Media活线程与峰值或明示未知的合同/实现接线，区分SDK线程、被调用原生库和调用方线程，保留原生调用不可强杀与Closing屏障。不能只改文档隐藏旧合同缺口。
3. 对所有行以同一候选做最终组合保护检查；当前矩阵是源码与已有记录的交叉映射，不是全部测试在同一DLL重跑的结果。
