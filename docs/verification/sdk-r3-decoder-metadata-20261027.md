# R3：独立解码输入槽与时间关联表计费

## 目标与改前证据

评审基线`3597a96`，对应R3 1.1i，MET-2 M-RECOVER/S5。只修独立解码器可控元数据存储；不改变输入64项、时间关联256项的既有上限，载荷帧预算另计，C签名/布局和平台不变。不改AM-RT、现场设备、公开制品。

改前真实C调用把控制通道压到1字节，创建默认独立软件解码器仍返回0且得到句柄；两个VecDeque随后按需扩容，但没有控制存储许可。该结果保留在本阶段`baseline.json`，不是用源码推算当实测。

主目标为存储分配前准入、固定容量、空闲仍计费及销毁后回收；保护预算失败不留对象、新旧reset重叠、旧代次/旧帧和继续解码、取消/关闭及像素/时间戳。没有设置整体提速或RSS下降目标。

## 实现与量化

私有Buffers拥有输入队列、时间关联表和最后析构的控制许可。创建前按有效queue_max_items及原256项时间表预留完整存储；两次try_reserve_exact后核容量，不在运行期扩张。构造原生解码器前完成预算检查；新旧reset都保留原存储直到成功替换，失败不提前销毁旧Inner。clear保留存储时不退账，最终释放Vec后才归还控制额度。

| 场景 | 结果 |
| --- | --- |
| 默认64输入槽/256时间记录 | 本机Packet=80、Timing=32字节，含Buffers本体共13,408字节、一个控制项；容量固定为64/256 |
| 控制额度比所需少1字节 | 分配前resourceExhausted，项/字节占用为0 |
| 填满两表后清空 | 容量不变、不扩容，空闲存储仍占13,408字节；最终drop后占用0 |
| 同预算构造第二个上下文 | 明确拒绝，旧存储和占用不变；释放旧存储后可再次创建，最终归零 |
| 输入槽参数0/65（私有构造） | 明确limitOutOfRange；公开0仍先规范化为默认64，未收窄公开输入 |

13,408字节是本机SDK布局存储，不是allocator/原生库或进程RSS。预留会比旧的稀疏、未记账空队列更早消耗预算，收益是额度完整和运行期队列/时间表不扩容，不声称内存必减。64 KiB控制总额不提高；在没有其他控制用量的默认64槽情形，存储本身最多容纳4个独立解码器，不能把max_decoders=8当作所有独立上限都可同时耗满的保证。调用方可减小输入槽，但不是保证总预算足够；RTSP像素worker走另一实现，不把该数字泛化成视频路数上限。

## 真实DLL及保护回归

候选C创建在1字节控制预算下返回8、输出句柄NULL。正常解码一帧后将控制预算降至1，NULL重置返回8，前后状态/解码代次/配置代次均为`[0,1,2]`；旧帧字节不变，再次提交仍解码相同像素。关闭/destroy和Context排空通过。

新定向单测2项，Media默认并行全组43通过/11 ignored；显式本机硬解故障转CPU恢复1项通过，不计作完整硬件矩阵。Release H.264/H.265共享帧、提交时钟、reset保留旧帧、每编码12张B帧（对FFmpeg参考最大RGBA误差0、PTS精确）、输入数量/字节/域拒绝计数、前包extradata低预算及NULL配置共享全部回归通过。

本包仅移动独立解码私有队列并新增预算准入，未改RTSP工作器或采样路径；不重复跑上一包同机RTSP压力、不将旧RTSP结果记作本包新测。两脚本只读已有合成输入，无新增服务器、发布器或大样本。
