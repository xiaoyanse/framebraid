# R3有界像素执行隔离

评审基线`1eb75d5c8dcffa487d6bb59e9debda22d83acac8`，目标见[测前卡](sdk-r3-pixel-worker-target-20261026.md)。仅FrameBraid main串行，不改AM-RT、不发布。R3仅本小项可独立收口，其余预算/故障/关闭矩阵与长跑保持开放。

## 变化与边界

原取流线程同步创建硬件设备、解码、回读和转换。现在只维护Gate及压缩分发，实际像素需求下启动一条scoped worker；启动前取得既有decoder许可，并与NativeDecoder复用同一Arc额度。MJPEG像素处理同样占槽。原生调用卡住时没有替代worker；需求消失或会话退出先停止队列，再由scope等真实执行完成，不能提前把Closing报Closed。

内部队列取AM_Q_ENCODED_STREAM的数量/字节及冻结上限，另至多一项在途；共享Payload已有实际字节Charge，队列只保存引用，元数据/参数副本另外预留。队列峰值/丢弃/重同步入既有计数；工作返回资源失败时也废弃参考链，避免漏送一个P帧后继续错误解码。源/配置/队列epoch贯穿执行，发布短锁内二次验证、维度事件和fanout，驱动调用在锁外。参数变化复用设备但清实际执行标记；在途旧帧不贴新配置。源最新接收时间改为单调最大，异步旧输出不把时间倒退。

## 证据

- 三项定向测试：像素处理被屏障阻塞时仍完成100项压缩入队/取出，像素队列不超过2项/64字节；过载前在途epoch失效，只从新的随机访问点恢复。该次生产队列局部循环131µs，不是网络FPS或真实驱动延迟收益。
- 20轮实际Execution线程阻塞/停止，未返回前decoder许可仍占用、第二次提交明确拒绝且无替代线程；scope结束后额度可重新领取。另100轮队列停止/唤醒不下溢。两者不等于完整Source API的100轮关闭或20轮断流认证测试。
- 候选A真实Release DLL：H.264/H.265各软件/D3D11VA四组回环参数切换通过，旧外部帧不变、连接代次不变；另H.264/H.265/MJPEG三组软件传输/像素/慢压缩消费者重同步通过，纯压缩没有解码器。S2三轮15个窗口见下一节。
- 尚未注入真实驱动永久挂死/任意厂商故障；受控屏障在生产worker调用原生工作之前，不冒充已经测过实际driver挂死。全SDK线程统计也未完成，Media通用threads字段当前不作worker数量证据，线程界限由额度与真实排空测试证明。
