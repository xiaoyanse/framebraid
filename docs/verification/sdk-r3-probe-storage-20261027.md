## 修复机制

- 探测缓存引用槽与 URL 载荷分账：按有效 cache_limit 精确预留引用槽，分配前以 metadata 控制字节准入，包含增长期间旧、新容量；仅在真正销毁旧容器后归还旧存储。条目单独占控制项目和 URL 实际容量，过期/失效清条目时，空闲槽仍计费。
- 本次结果优先：结果准入不足时销毁完整缓存容器后再重试，不能只 clear 条目并提前归还仍常驻的存储。缓存槽或 URL 分配/预算失败只跳过缓存，不抹掉已经完成的本次探测观察。
- 入口先核有效 Context，再借用扫描最多16个、每个最多4096字节含终止符的 UTF-8 字符串。扫描使用固定栈数组；计算结果本体与 Arc 头、ABI Box、CString 引用数组、候选数组、字符串含 NUL、临时凭据字节后，才申请额度并复制。
- 两个结果 Vec 以 try_reserve_exact 构造并核实际 capacity；CString 先预留含 NUL 的字节后构造。临时凭据真实销毁后，许可才收缩到结果拥有字节；移交后维持至结果释放。分组线程句柄、命中观察及索引改为固定栈数组。
- 仍支持不识别协议候选返回 unsupported；缓存身份、源凭据变化 generation、成功300秒/失败30秒时效语义保留。
