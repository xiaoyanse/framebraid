# GPU 主线 M1 MET-2 对照：真实 Pose CPU vs CUDA（2026-10-28）

测前目标卡 `.local/evidence/gpu-m1-met2-20261028/target.md`（冻结件同 met2-s3：模型 `80fb5f58…`、输入 PNG `c0309f14…`）。SDK 本仓 Release am_vision；CPU 运行库 v0.1.0 候选 onnxruntime-cpu，CUDA 运行库 `.local/runtimes/ort-gpu-131-final`（见 [CUDA 验收](sdk-gpu-m1-cuda-20261028.md)）。子进程隔离每轮独立加载，交替 3+3 轮、每轮 20 次真实 PNG→Pose 同步推理。本机 RTX 5060 Laptop。脚本 `scripts/sdk/benchmark-gpu-compare.py`，原始数据 `.local/evidence/gpu-m1-met2-20261028/run1/rounds.json`。

**结论（同负载、同输入、真实模型）**：
- **CUDA 同步推理 P50 约 26.7～28.6ms vs CPU 约 97～116ms——3.6～4.2 倍加速**；CUDA P95 波动远小于 CPU（30～41ms vs 115～337ms），尾延迟更稳。
- CUDA 侧代价：首次会话加载约 0.5～1.4s（含 EP 初始化与 CUDA 上下文），比 CPU（约 0.18s）高；进程内会话复用时该项摊薄。
- 各轮 max 的偶发尖刺（1.1～11.3s）为进程冷启动首帧（子进程隔离设计所致），不影响 P50/P95 结论。

**输出对拍：不一致（如实登记）**。CPU 与 CUDA 的输出指纹不同（`bebb4c7c` vs `9393b602`，按前 64 字节+尺寸指纹）。这符合预期中的 EP 数值差异（CUDA EP 的算子实现/归约顺序与 CPU EP 不同），但本对照的指纹法（前 64 字节哈希）**不足以区分"数值容差内的正常差异"与"语义错误"**——判定需按 met2-s3 口径（有效检测行/关键点级对拍）。该深度对拍列入 M1 收尾待办，本记录不宣称输出等价也不断言错误。

**边界**：单图单模型同步路径；不含异步/批量路径 GPU 对照（后续 M2 阶段随 GPU 帧管线一并）；样本 20/轮为快速对照，非严格 MET-2 目标卡三轮全量（目标卡合格判据 20/20 成功已满足）；GPU 引擎占用未观测。CUDA 加速结论限定本机 RTX 5060 + 该 Pose 模型 + 同步单帧路径。
