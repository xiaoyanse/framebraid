# R2 H2.0d 设备引用复用验证（2026-10-26）

本地Windows x64 Release、合成1080p H.264，源基线`9252a01`。没有连接现场相机、修改AM-RT或替换公开制品。实现合同见[原生硬件设计](../design/native-hardware.md)，任务为R2 H2.0d；H2.1～H2.4及H5仍开放。

## 实现和范围

`CpuDecoder::reconfigure`为新codec上下文取得同一设备的独立`av_buffer_ref`，运行库Arc覆盖其寿命。硬件像素选择回调绑定新Box，执行验证初始为空；原decoder没有被消费或修改。`software_reconfigure`明确创建独立CPU上下文，不推测或执行输入重放。设备创建前仍检查目标codec配置，防止不支持时触碰驱动。

这是兼容Rust新增；C ABI签名、枚举、布局、内存和默认策略不变，无生成物变化。调用方仍负责参数集、关键帧、源代次与全局预算；本轮不声称DLL自动选择/恢复完成。现有语言封装、快速接入与公开支持范围不变，不新增无装配的语言接口。

## 实测

`cargo run --release --example hardware_reconfigure -- <runtime> <single-au-1080p.h264>`。Intel Arc 140T、D3D11VA、LUID112296：

- 首次真实选择的设备创建次数1，参数重建及显式CPU重建后仍为1。
- 原上下文持有PTS2待输出帧时，非法预算重建被拒绝，旧帧仍可正常输出。
- 新上下文真实输出前不报告硬解；销毁原上下文后，新上下文PTS3解码及回读成功。
- 同一后端三个输出像素完全一致；不将GPU/CPU不同转换路径声称字节一致。
- 显式CPU重建输出PTS4、再重建CPU输出PTS5，像素一致，不新增硬件初始化。

最终源版本同进程交替构造12轮，前2轮预热、10个样本，**仅计构造，不含解码、回读、输出和析构**：每次重新创建设备29,100～31,403µs，中位数29,694.5µs；复用设备25～30µs，中位数27.5µs。这是参数上下文重建开销下降，不是每帧吞吐或端到端延迟提升；没有据此关闭整链性能验收。早一轮28,545～31,488µs与25～34µs原记录保留，不覆盖旧结果。

最终证据`.local/evidence/h2-device-reuse-final-20261026.json`，早一轮`h2-device-reuse-20261026.json`；运行库`.local/runtimes/ffmpeg-h2-20261026/runtime`。本地`h2-device-reuse-manifest-20261026.json`绑定最终源文件/EXE/输入/运行库/结果摘要，未提交二进制和样本。
