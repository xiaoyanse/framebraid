# R3 共享源别名登记回收验证

## 范围与目标

评审基线为 `ca53722`；只修复 Media C ABI 共享源的内部弱引用登记，不改变公开函数、布局、队列或凭据合同。测前目标：一个常驻源、重复打开并销毁256个共享别名、期间没有状态事件，登记列表不能随历史操作线性增长；常驻源保持有效。保护指标：共享身份一致、凭据轮换、最后所有者关闭、回调注销屏障。

## 问题与修复

`sources/api.rs` 原来每次打开只向 `SharedSource.sources` 追加Weak，只有状态事件才清理死亡Weak。长期等待凭据且无事件时，反复开关别名会累积旧Weak，并让已销毁Source的Arc分配体滞留。现在在已有登记锁内、加入新别名前回收强引用数为零的条目；仍活着的句柄和共享所有者不受影响。

## 审查与同步

以本基线差异检查正确性、安全性、维护性、性能：清理与加入同锁；Weak::strong_count为零后不可重新升级；不移除活对象，不更改域句柄和所有者计数。致命项0、阻断项0；未验项如上。项目没有 `.Codex/memory/patterns` 目录，不伪称已读不存在清单。

C ABI、生成器、语言调用方式未变，因此不改ABI冻结或高层接入说明。Unreleased、交付状态、R3设计/任务和预算矩阵同步；来源修订保留原始提取清单。此为本地源码定向验证，不声称新Release DLL已验或对外发布。
