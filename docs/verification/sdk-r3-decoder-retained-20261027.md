# R3：独立解码配置、参数缓存与无列表NAL校验

## 范围与改前证据

评审基线`d0c3ebfb57ea5498955a76ec56e72cae9329761f`，对应R3 1.1h。MET-2 M-RECOVER/S5主目标是SDK配置/参数缓存先准入并持续计费；附带M-CONVERT机制指标为消除NAL校验列表分配。保护C ABI、既有NAL接受范围、解码像素/时间戳、失败重置和外持帧；不改AM-RT、现场设备或公开制品。

旧Release在Context帧预算1 MiB下，接受2,097,193字节extradata；创建及重置都返回OK。重置代次从`[state=0,decoder=1,config=2]`变为`[0,2,3]`。这是真实C调用复现，不是从源码推断；输入为原合成H.264样本的参数集加有效filler NAL，不改变公开GOP上限。

## 实现及定向结果

- 配置复制前预留帧字节，成功后由不可变Arc拥有者保持至最后引用释放；ABI原始借用指针清零。reset(NULL)不克隆extradata，每个新原生上下文自己的参数缓存仍独立计费。
- Gate先借用解析并规划最终SPS/PPS/VPS，整体校验、预算及全部分配成功后再提交；拒绝不改旧缓存或参考链标志。参数先变后还原仍保守等待新随机访问点。重配置的Annex B序列化暂存单独预留并覆盖同步原生调用寿命。
- 新旧构造重叠占用均保留；低预算可比旧实现更早明确拒绝。保证create/reset构造失败不破坏旧配置/代次，不扩展为所有原生驱动错误都可事务回滚。
- 兼容新增Rust `visit_access_units`，同步借用输入、不建NAL列表。错误前可能已调用部分访问者，调用方须整体成功才提交状态。旧Vec入口保留，历史最多4097项接受边界不收窄；不是全链路零拷贝。

| 定向用例 | 已验证结果 |
| --- | --- |
