## 发现与修复

旧抓图Record逐项计了本体，但HashMap桶容量未计，删除后保留的桶不退物理存储；Flight、频率缓存/消费者及弱订阅登记也只有数量或业务约束。最近图缓存登记错误原先提前返回，会绕过Flight结果发布/唤醒/移除，新增长拒绝使该分支成为必须正确处理的实际路径。

- 请求、Flight、最近图、消费者、活动订阅改为按键有序有界连续表，分配前预留实际槽和新旧增长重叠，失败保留旧表；清空后容量持续计费到State销毁。非二次幂硬限不向上扩容，查找二分、插入删除有界搬移，不宣称整体加速。
- 原请求控制项token仍逐记录保留，字节由表本体计，不能重复按len计同一存储；元数据不新增外持项或Context.buffers屏障。Flight本体另占控制字节，原始JPEG/像素仍按数据额度与既有拥有者存活。
- 记录表准入成功后才分配ID；受理前失败不发布ID。受理后工作线程的Flight分配失败则保留ID并给失败终态，可fetch错误/ack；不能把异步受理等同图片成功。
- 缓存登记失败进入本Flight统一结果，再通知等待者并按指针身份移除在途索引，后续可重新抓图。停止/源切换的既有保护保留，不强抢在读或外持图片。
- 活动订阅登记剔除已释放名额的Closed旧对象；句柄/本体许可仍等销毁。统计用固定4项栈快照，不为查询再建Vec。索引硬限与允许新增源/订阅的可下调限额分开，降低新增源上限不撤销已打开源。
