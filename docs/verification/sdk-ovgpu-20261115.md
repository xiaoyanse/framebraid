# sdk-ovgpu OpenVINO 原生 GPU 设备定向验证记录（2026-11-15）

范围：清偿 v0.8.0 诚实边界「OV native 仅 CPU 插件，定向 GPU=notSupported」——backend=4 消费设备定向选择器（合同 §3.5b，C ABI 零变化）。本机双 GPU（NVIDIA RTX 5060 Laptop 10de:2d19 + Intel Arc 140T 8086:7d51，核显同设备 4 个 DXGI 实例），Windows 11 Pro 10.0.26300。工作分支 sdk-ovgpu-wip。

## 运行库评估（任务第 1 项）

盘上 OpenVINO 运行库两套，llvm-objdump 导出表对比（2026-11-15 实测）：

| 运行库 | OpenVINO 版本 | openvino_c 导出 | GPU 插件 | 备注 |
| --- | --- | --- | --- | --- |
| `.local/runtimes/openvino-native` | 2026.1.0（vcpkg 线） | 211 | 无（仅 CPU 插件） | E1 历史基线（2026.2.1 wheel / 2026.1.0 vcpkg / 2025.3.0 wheel 三线矩阵的当前盘上代表） |
| `.local/runtimes/ort-ov-124-final` | 2025.0.0（官方 onnxruntime_openvino 1.24.1 wheel，materials-lock 登记） | 205（2026 线严格子集） | 有（openvino_intel_gpu_plugin.dll，依赖 OpenCL.dll+SETUPAPI.dll 驱动店发现） | 盘上唯一含 GPU 插件闭包 |

- **符号对照**：绑定所用 30 符号（28 FFI + ov_free + ov_get_last_err_msg）在 205 导出中全存在；缺失 6 符号（ov_core_add_extension/字符串张量对/日志回调对/gpu config file key）均不在绑定内。新增 3 符号（ov_core_get_available_devices/ov_available_devices_free/ov_core_get_property）两线均在，签名按 2025.0.0 tag 头文件（commit 1f68be9f，与 DLL 内嵌 buildNumber `2025.0.0-17942-1f68be9f594` 一致）逐项核对。
- **关键发现——元素类型序数分界**：2025.0.0 的 `ov_element_type_e` 为旧序数（UNDEFINED=0/DYNAMIC=1/BOOLEAN=2，五类全表 +1：F32=5），2025.1.0 起并入当前布局（DYNAMIC=UNDEFINED=0、BOOLEAN=1，F32=4）——E1 时代「2025.x/2026.x 两线一致」结论覆盖的是 2025.3.0+，对 2025.0.0 不成立。**不做适配直接用该运行库会全模型失败（f32 端口报序数 5 未映射）**。处置：ov_sys 增 `ElementLine`，装载期按 buildNumber 前缀 `2025.0.` 选旧序数表，其余（含未知版本）按当前表；两表互不接受对侧独有序数。头文件对照链：2025.0.0/2025.1.0/2025.3.0/2026.1.0 四点（GitHub tag 逐个取 ov_common.h）。
- **目录策略（并存，不切换）**：openvino-native（2026.1.0）保持 CPU 基线（E1 历史矩阵锚点，vcpkg 闭包无 GPU 插件，换线零收益）；ort-ov-124-final 作为 GPU 会话验证载体（唯一含 GPU 插件）与 E1 矩阵新增第四验证线。进程内单线（OvApi 一次装载一套 openvino_c），跨进程互不影响。
- **环境事实**：本机无注册 OpenCL ICD（HKLM Khronos\Vendors 缺失，System32 仅 Khronos loader）；GPU 插件经 Windows 驱动店发现（SETUPAPI）实测可达核显——探测脚本实证 available devices = [CPU, GPU, NPU]，`FULL_DEVICE_NAME[GPU]="Intel(R) Arc(TM) Graphics (iGPU)"`，`AVAILABLE_DEVICES[GPU]="0"`。

## 实现要点（对应任务第 2/3 项）

- `engine/openvino.rs`：`compile_model` 设备参数从硬编码 `c"CPU"` 贯通为 `CompileDevice`（Cpu=零变化 / Gpu={selector, vendor}）；GPU 解析=`ov_core_get_available_devices` 枚举 → `pick_gpu_device` 纯函数（needle/instance 子串消歧 → 多设备域无命中拒绝 → 单 GPU 域回退 → 厂商核对词把关）→ 按选中设备名编译；无 GPU 域/定向不可达=候选失败 stage=`gpu_device`（native_code=None 逻辑拒绝，失败详情附 OV 设备域快照）。
- `sdk/device.rs`：backend=4 分支从 `sdk.notSupported` 解锁为 DXGI 存在性校验+厂商核对词（DxgiAdapter 增 VendorId；vendor_token：0x8086→intel/0x10DE→nvidia/0x1002|0x1022→amd/其余 None）；返回值改 `ResolvedSelection{targets, ov_ep_gpu, ov_native_vendor}`。
- `sdk/model.rs`：need_dxgi 域纳入 backend=4；OV 原生候选按「selector 在场=Gpu」构造引擎目标；device_label 按引擎实际编译设备回填（`OpenVINO:GPU`/`OpenVINO:CPU`）。
- **定向粒度边界（如实）**：OV C API 无 DXGI↔OV 设备级映射（无 LUID/PnP 关联属性），OV 设备全名与 DXGI Description 文本不同源（本机核显 DXGI=`Intel(R) Arc(TM) 140T GPU (16GB)`、OV=`Intel(R) Arc(TM) Graphics (iGPU)`——型号子串如 "140t" 只命中 DXGI 侧）；因此定向语义=DXGI 存在性校验（合同域）+OV 域内 FULL_DEVICE_NAME 消歧（名称可命中时）+单 GPU 域回退+厂商级把关（防跨厂商静默换卡）。同厂商多实例在 OV 域内的次序不与 DXGI 序合同挂钩；HETERO/MULTI 设备串与 DEVICE_ID 属性属 OV 自有能力，不进本合同。

## 诚实边界

- 同厂商多实例（如本机核显 4 个 DXGI 实例形态）在 OV 域内的次序映射不做合同承诺。
- GPU 数值带隐式 FP16 漂移类（上表原始值）；对拍门为统计量级，非逐元素。
- 真实模型（YOLO 级）吞吐未测；本批只验正确性/定向语义/回退矩阵。
- OV EP 线（backend=1）维持 v0.8.0 状态（provider Error 127），不在本批范围。
- GPU 帧直传（§3.3a）对 OV 原生引擎仍为后续增强（输入仍 CPU 拷贝路径）。
