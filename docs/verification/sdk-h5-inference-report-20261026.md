2026-10-26；评审基线`5449e79`，SDK main串行阶段保存，无AM-RT修改/升级、无发布。继[核心阶段](sdk-h5-selection-core-20261026.md)，新增两项兼容C导出及Python/C#便捷调用，不表示H5整包完成。

## 实施与审查

- `amv_probe_inference_hardware`显式、有界发现CPU可用逻辑并行度及CUDA驱动设备，最多16项；无ORT共享帧context也可使用。缺驱动/失败/未知写入报告，不当作真实加速可用。原生调用之间检查软预算，不强杀驱动。
- `amv_get_inference_hardware_report`只读设备缓存和SDK域累计provider/执行观察，不触发探测或重装运行库。schema最小合同纳入ABI1.1本地r8，旧1.0/1.1初始化和74结构/547偏移、旧枚举保留。r7原冻结保留并绑定SHA；旧工件按5449e79复核，开发绑定与同提交DLL配套，不扩大公开v0.1.0。
- 缓存16KiB、查询暂存48KiB，使用32KiB定容直接序列化，无JSON树副本；最坏16个控制字符设备名转义的容量有单测。内部控制缓存不算调用方外部租约，不阻塞关闭。并发查询/其他控制对象占额时明确resourceExhausted，不扩大默认64KiB控制预算。
- 关闭中/完成后返回空快照，不重建服务、不探测、不暴露旧活动；destroy后不再使用。查询持只读活动许可与最终关闭互斥，driver调用不持报告锁。运行库就绪改原子快照，避免查询等待原生初始化锁；测试在初始化锁被持有时查询仍完成。
- 正确性/安全/并发/性能审查纠正了初稿暂存超默认额度，采用有界直接序列化。测试初稿错误地尝试重新抬高已降低队列额度，现改为独立小context，不放宽旧“只降额度”合同；空指针断言按既有nullArgument错误修正。无未处理阻断项；设备发现/JSON查询/已有模型模块职责独立，不扩成监控平台。
