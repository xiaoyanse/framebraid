# R1-M1 / S1 连续GOP资源量化验证

2026-10-26，本地阶段保存，不发布、不改AM-RT。用户已授权从MET-2文档阶段恢复SDK main串行开发。本包只新增测量工具、定向测试与文档，**SDK核心及公开ABI未改**。

## 身份与方法

测前要求见[目标卡](sdk-met2-s1-target-20261026.md)，评价依据[MET-2](../PERFORMANCE_ACCEPTANCE.md)。工具源码以`8d8a1f1`为观察仓库基线；实际加载的Release Media DLL如实报告`b065bf10181c74ace5c8850672a5d75fc82e2869 / dirty`，SHA-256为`92d0af2c24fdfadbc9f00f82477ee96539263f74397cf6d64a8d6d9c65c9f6c6`。**这不是088f821/main重建或干净提交的制品证明**，也不是对旧公开v0.1.0的改前/后比较；同一DLL内的CPU/硬件资源取舍有效，核心优化前须另冻结匹配候选。

H.264自产MP4为1920×1080、30 FPS、yuv420p、GOP30、2个B帧、10秒；SHA-256 `923c1062a97a5f61bff8497c1d71cab70dc1c64e96dc1a9222cf3913c4016529`。ffprobe取封装边界，SDK实际解码，备料/完整输入复制在测量外；定拍提交、CPU RGBA视图/元数据校验与及时归还，解码响应含参考帧重排。不是相机曝光、网络、浏览器显示或模型精度。

每轮预热2秒、稳态6秒，CPU/硬件三轮交替，另各一轮观察关闭。CPU为进程用户态+内核态，含Python、SDK、FFmpeg及采样线程，整机归一分母为当前进程可用16个逻辑并行度。PDH按PID/LUID/引擎采样，4Hz、有限条数，不把GPU总百分比当解码负载。实际硬解为Intel Arc 140T / D3D11VA，LUID `0x00000000_0x0001B6A8`；其他GPU不据此验收。

每轮期初2在途+窗口输入180=窗口全部输出180+期末2在途；全部提交240帧最终均排空，0拒绝/丢弃/重复PTS/源代次变化。全部178个测量输入窗口内响应均≤200ms，实验最低171帧线满足；窗口误差最大0.477ms，提交节拍P95迟到最大0.588ms。未把B帧尾项算丢失，未把预热帧交付算作测量输入收益。

- CPU中位数差为 **-0.078125 CPU-s（-9.80%）**，小于测前0.1 CPU-s且10%的调查门，亦小于CPU组A/A跨度：**CPU卸载收益证据不足**，不宣称优化成功，也不据此判硬解功能失败。硬解GPU VideoDecode非零实例平均9.55%～9.66%，其他引擎分别留raw，不相加。
- CPU/硬件响应P95中位数差约0.623ms；不是旧局部`copy_rgba`时间，也不是额外GPU处理全部耗时。B帧重排使响应含等待后续输入，不能写成137ms纯解码耗时。
- 采样进程私有内存峰值：CPU约67.3～107.2MiB、硬件约128.0～131.5MiB；同进程多轮含原生缓存/历史初始化，且只是采样峰值，不是绝对峰值或泄漏结论。
- 观察关闭控制：CPU 0.734375 CPU-s/P95 137.1999ms，硬件0.750000 CPU-s/P95 138.0008ms。均处短测波动附近，不从单轮控制相减宣称精确开销。采样线程初始化外CPU最高0.078125s/轮；完整线程CPU与初始化分别留raw，不混入稳态卸载判断。CPU无GPU实例时为未知，不伪造0。
