## 发现与登记

- **R2-SAMPLE-01复现**：现代码按实际fanout时间的严格最短间隔判到期；固定30 FPS输入的实际到达/处理抖动会错过临界到期点，与观察到的接近一半30 FPS交付一致。当前实测只证有缺口，不排除输入突发、同步解码等共同作用，不把它唯一归因CPU慢/硬解失败。保持原合同，后续修订节拍应说明最大速率、抖动/突发和兼容语义，不静默改成追帧模式。
- **R2-HW-STREAM-02仍开放**：当前同步读流/像素处理不能只凭“不重连”证明压缩低延迟隔离；本次仅单源/CPU/普通消费者，未注入慢驱动。
- **R1-COUNT-01工具修正**：活流`external_held_items`包含队列/正在生成的共享Frame，不能直接认定调用方泄漏。初次正式运行在第14个窗口触发工具误判；保留13份成功raw及failure，修正停源后检查，仅另补30和混合的缺少第三轮。正常15份有效窗口，另1次因观测错误失败；没有更改SDK额度或把失败删除。补测混合活流计数1→停源0，证明需分状态核计数。
- 固定4秒10 FPS×80%=32帧，实际窗口几百微秒尾差会使显示值为7.999；复核按测前窗口的整数32帧线判断，实际FPS仍按墙钟显示，不因四舍五入制造额外失败。30 FPS的24线不变，所有三轮仍不足。
- 后补30 FPS档`frames_dropped=3`为context累计值，含热身/关闭前阶段；原13组未采这个字段，不能宣布全矩阵零丢帧。重新连接/慢消费者/尺寸变化、HEVC/MJPEG与长期压力均未完成。
