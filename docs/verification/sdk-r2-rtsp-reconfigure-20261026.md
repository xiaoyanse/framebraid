# R2 H2.3c RTSP参数重建设备复用

本地main评审基线`72f86cdd7601464e91c24dbf89726d2ee757dab4`，测前目标见[目标卡](sdk-r2-rtsp-reconfigure-target-20261026.md)。本轮只关闭参数重建设备复用接线，不关闭H2整包、真实采样帧率不足或读流隔离；未改AM-RT、未发布。

## 实现与验证范围

原RTSP在参数集变化时丢弃NativeDecoder，下一关键帧重新探测/创建设备。现在Gate发现变化后暂停像素输出并保留旧上下文，下一真实随机访问点用`reconfigure`取得原设备独立引用、复用已有decoder槽；预算与新上下文成功后替换。构造和析构不持状态锁，成功后清实际执行、保留原选择报告并递增decode_generation，真实出帧才重新报告硬解。

CPU重建保守预留新工作额度，新旧暂存重叠也计费；预算不足保留旧上下文等待下个随机访问点，不向旧上下文发送新配置。原生构造失败沿pixel_failure停止本次像素代次、按既有策略等待下一关键帧恢复CPU，不在当前RTSP包上历史重放。配置临时副本预留额度；不新增线程、decoder槽、公开布局或能力位。驱动/原生DPB仍不是SDK托管内存硬限。

## 结果

- **真实原生生产helper**：H.264/H.265分别CPU、PREFER_HW四组合，256×144→128×96。硬件实际为本机Intel Arc 140T D3D11VA，初始化各创建设备1次，参数重建新增0次；CPU两组合始终0。`max_decoders=1`下成功切换，另取decoder仍明确拒绝，收尾额度归零。
- 非随机访问点不重建；CPU预算拒绝后原上下文PTS保留，额度恢复可重试。重建后实际硬件状态清空，真实新帧再验证；外部旧帧尺寸和完整像素不变。注入原生分配失败时记录AllocationFailed，像素恢复不改变压缩源及配置代次。
- **新构建Release DLL、真实回环RTSP**：随机127.0.0.1端口、自产H.264/H.265流交替两种尺寸，CPU/PREFER_HW四组合全部通过；两个尺寸均交付，像素PTS/帧ID及压缩seq单调，源代次不变，decode_generation随参数重建增加，选择报告未重新生成，关闭后外部持帧计数0。
- 核心机制收益是“不再因每次参数变化重复创建设备/探测”，不以单次构造时间推导播放帧率、CPU卸载或多路容量。四次重建局部耗时保留raw，不作为统计充分的提速结论。
