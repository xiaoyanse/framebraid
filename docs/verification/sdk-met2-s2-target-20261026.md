# MET-2 S2 真实RTSP采样与混合消费测前卡

测前固定，2026-10-26。使用当前main重建的Media Release DLL、既有匹配FFmpeg及S1固定自产1080p30 H.264 GOP视频，随机回环端口MediaMTX+FFmpeg循环发布，不连接现场设备。

- 主目标：补R2 1.2在实际网络/系统时钟下的交付、参考链与资源分母，核单个5/10/30最高FPS消费者和5+10+30混合消费；另纯压缩消费者证明不启动解码。不是历史二进制A/B，不把不同交付需求的CPU差异称优化收益。
- 每档先2秒热身，再4秒固定窗口、三轮交替顺序；有界4帧/32MiB像素队列、4Hz资源观察、唯一帧/PTS/代次、接收→消费的同机QPC年龄。C帧视图只核尺寸/格式/指纹前缀/身份，及时归还；不全图复制到Python，不验人员精度。
- 实验保护线：压缩输入≥27 FPS；5/10/30每路实际交付先对照配置的80%（4/8/24 FPS），接收→消费P95≤250ms，无重复、错代次或外部持帧残留；0新代次/硬件降级；线程及字节预算不放宽。80%是本场景调查线，不改变`sampling_max_fps`只保证最高值、非稳定最低FPS的合同；不达线如实登记，不能靠换阈值称验收通过。
- `sampling_max_fps`当前用严格最短间隔；真实抖动可能让到期机会推迟。按本次真实结果决定是否另设计可选节拍算法，不在测试中改SDK时间或隐式放宽上限。
- 资源：进程CPU含调用方轮询/SDK/FFmpeg/采样线程；造流器与MediaMTX是独立进程，不混入分母。GPU和原生转换次数不可测时记未知；既有虚拟时钟转换消融保留，不冒充本次真实流转换计数。
- 预算：正常三轮最多15个4秒窗口，最多3分钟；短烟测单列。固定源本身不足供帧、因工具错误失败均保留，不追加无限测试。每轮raw、DLL/依赖/源/工具摘要、工具源码保存新`.local/evidence/met2-s2-20261026-*`；服务配置与日志只在对应`.local/tests`目录。
- 出口：所有像素/压缩订阅、共享源、context先关闭归还，最后仅停止本轮发布器与MediaMTX。源码/公开ABI/宿主不因量化而变更。与S1/S3一起形成R1测量前置，HEVC/MJPEG、动态尺寸、生产耐压仍独立验收。
