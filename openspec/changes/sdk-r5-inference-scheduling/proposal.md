# Proposal

## Why

用户要求前移 R5 可独立优先项。先修现有调度竞争与失效积压，后续在数据支持下增加可关闭组批和后端策略。

## What Changes

- 2026-10-26 指标复核采用[MET-2](../../../docs/PERFORMANCE_ACCEPTANCE.md)，本包指标组M-SELECT/M-SCHED，场景S3/S4，故障配合S5；硬件选择以策略/可用性/真实执行为主，调度以准入/等待/过期/公平性或离线有效吞吐为主；CUDA不要求默认更快，组批不以批次均摊当逐帧延迟。 本轮只修订文档，保留既有实现及原始证据。

- 用户于 2026-10-26 要求将推理硬件探测和自动选择前移至自动组批之前：沿用 CPU/OpenVINO/CUDA 边界，补目标模型实际可用性、策略选择、回退和恢复诊断；不是增加设备台账或后台探测服务。

- 低等待、公平调度与显式组批，具体任务及量化条件见 tasks.md。
- 复用既有预算、所有权和 ABI；新增公共能力先同步合同和生成器，保留原冻结历史。
- 原始性能证据只放 .local，公开摘要不包含凭据、设备地址和客户图片。

## Capabilities

### New Capabilities

- `inference-scheduling-policy`：低等待、公平调度与显式组批的可验证行为与性能边界。

### Modified Capabilities

无已有主规格；不修改宿主业务或既有公开 ABI 的兼容语义。

## Impact

仅影响 FrameBraid 核心、受影响测试、基准及文档。第 1 组和 H5 只依赖 R1 与现有模型合同；第 2～3 组依赖 R1～R4 与真实代表模型证据。 不修改 AM-RT，不自动发布或增加平台承诺。
