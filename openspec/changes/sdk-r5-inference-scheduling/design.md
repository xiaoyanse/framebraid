# Design

## Context

核对基线 `db0cb1014be04334869bdea914347cd5f060ce71`，范围见 proposal。用户授权 main 串行、阶段测试量化及本地提交，使用 OpenSpec 恢复推进。

## Goals / Non-Goals

目标：低等待、公平调度与显式组批，以 [完整路线](../../../docs/ROADMAP.md) 为范围依据。
不做业务、UI、凭据持久化或第三个 DLL，不更改 AM-RT 固定依赖；基础推理硬件探测/选择已由用户明确纳入，其他扩展不自动实施。

## Decisions

2026-10-26 用户将 H5 硬件探测/自动选择前移：只依赖 R1 的身份/预算和现有模型合同，不等待 R2～R4 或自动组批；后续与 R3/R4 联合复验。CPU/OpenVINO/CUDA 使用现有进程装载和单加速后端共存约束，不为了自动选择在同一进程强行并存不兼容运行库。CPU 为确定性基线，调用方显式给定允许后端/优先级或选择自动策略；strict 禁止静默回退，允许回退时必须报告请求与实际 provider、设备及原因。自动选择不是每帧测速或迁移模型，不宣称最优性能。

只枚举硬件不能判断可执行；分别记录设备、依赖、provider、目标模型会话及真实执行。探测/预热显式启动且有超时/并发预算，查询只读，瞬态负结果可刷新。OpenVINO 当前 CPU 定位保持，不将 NVIDIA 检测泛化成所有加速设备；GPU 可见但依赖缺失给明确诊断。运行期失效只按模型生命周期和已接受请求合同收口；未确认状态不自动重放，活输入持有到原生读取完毕。ABI 新增必须先改设计/生成器及冻结演进记录。

第 1 组先于 R2 实施，延续显式 batch 入口和公平开关；自动攒批与后端运行期策略为第 2 组，依赖模型合同、实测容量及接口评审，不能通过重定义旧 AUTO 语义偷偷开启。

第 1 组和 H5 只依赖 R1 与现有模型合同；第 2～3 组依赖 R1～R4 与真实代表模型证据。

共同评价改用[SDK量化指标与验收目标 MET-2](../../../docs/PERFORMANCE_ACCEPTANCE.md)：区分同路径回归与跨后端资源取舍。每包测前确定主目标、保护指标、计时边界和目标卡，按A/A波动及绝对/相对实际影响评价，不把5%作为统一通过/失败线。原始数据及旧警戒事件保留；功能/安全、机制变化、收益与长期稳定性分别验收。CPU时间、GPU引擎、有效交付及公平性按场景采集，不以单帧耗时替代卸载收益。旧工具和预算保留。用户已授权恢复，独立S1资源及S3真实Pose CPU工具/基线已补，缺项继续按R1前置标定；不把缺EP回退控制当加速EP真实执行。

## Risks / Trade-offs

H5分组实施以`docs/design/inference-selection.md`为合同：Rust先补有界允许列表、阶段诊断及短锁认领，后续再接真实DLL导出/只读矩阵/恢复。不能以基础组测试关闭H5.1～H5.4。不同硬件后端的单帧耗时取舍与同策略代码优化警戒分开；硬解较慢不单独认定缺陷，需量化CPU卸载与并发/延迟预算。

- 原生调用不可强杀 → 活输入与租约持有到实际读完，取消先记录意图。
- 测量可能干扰处理 → 外部聚合/可关闭观测，单独测自身开销；不作每帧同步磁盘 I/O。
- 参考项目并非可复制交付 → 借鉴机制与用例，若搬代码先确认许可。
- 未有目标设备/模型 → 保留未验项，先完成可独立 CPU/合成链路，不伪造硬件或业务精度验收。

## Migration Plan

H5资源竞争修订在不改C布局/签名前提下采用逐候选线程预留，避免列表中的OpenVINO最大配置阻断可以运行的CPU候选。共用基础额度保留一个执行器/模型许可，候选之间只调整额外线程，失败保持原额不超配；原生会话创建返回且释放后才能调整下一候选。新Rust admitted帮助入口允许FFI接现有预算，不复制模型读取/校验/选择循环，SDK准入失败与真实EP忙/显存故障分开验收。

先基线再候选，完整小包自查后本地提交；核心来源变更显式修订 sdk-source-revisions.json，保留原提取指纹。回退按提交恢复代码/合同/绑定，不自动回退宿主或替换已发布包。验收与文档随每组同步；OpenSpec 勾选须有当前候选证据。

H5.0b先接显式推理probe和有界缓存JSON报告：ABI1.1兼容增加两函数、无结构扩展，缓存占内部控制额度不阻塞关闭；查询不做探测，缺驱动与未知不冒充可用。模型C策略/旧矩阵缓存迁移和恢复继续未完成。

## MET-2 主目标与保护指标

指标组M-SELECT/M-SCHED，场景S3/S4，故障配合S5。硬件选择以策略/可用性/真实执行为主，调度以准入/等待/过期/公平性或离线有效吞吐为主；CUDA不要求默认更快，组批不以批次均摊当逐帧延迟。 对应验收值在下一候选测试前填写目标卡，未标定不捏造百分比或路数；历史已完成项不因改指标自动升级为整包完成。

H5 r9将已有Rust选择接至四个兼容新增C导出，详见ABI §3.2。旧desc和入口不变；显式新列表最多3项，加载ID防context单槽并发串读，成功模型独立缓存并在实际Run后更新。缓存/查询按control额度，不能跨原生执行持查询锁。旧CUDA:0静态字样不能用于非零设备，新模型和结果须各自拥有设备/失败字符串，结果可跨模型关闭存活。完整加速/故障/长跑不以本阶段关闭。
