# Design

## Context

核对基线 `db0cb1014be04334869bdea914347cd5f060ce71`，范围见 proposal。用户授权 main 串行、阶段测试量化及本地提交，使用 OpenSpec 恢复推进。

## Goals / Non-Goals

目标：全链路有界压力和故障恢复，以 [完整路线](../../../docs/ROADMAP.md) 为范围依据。
不做业务、UI、凭据持久化、第三个 DLL 或扩展池 E1～E4 自动实施，不更改 AM-RT 固定依赖。

## Decisions

复用既有队列、租约和通知线程；先追踪中转所有权，再修预算缺口，不另建后台作业中心。原生库/驱动内存与 SDK 可控预算分开。

复用 R1 预算及 R2 候选；关键安全缺口发现即优先修，不将修复推迟到长跑。

共同评价改用[SDK量化指标与验收目标 MET-2](../../../docs/PERFORMANCE_ACCEPTANCE.md)：区分同路径回归与跨后端资源取舍。每包测前确定主目标、保护指标、计时边界和目标卡，按A/A波动及绝对/相对实际影响评价，不把5%作为统一通过/失败线。原始数据及旧警戒事件保留；功能/安全、机制变化、收益与长期稳定性分别验收。CPU时间、GPU引擎、有效交付及公平性按场景采集，不以单帧耗时替代卸载收益。当前工具和旧预算未改，缺项先按R1新增前置标定；本次仅文档，不自动恢复代码开发。

## Risks / Trade-offs

- 原生调用不可强杀 → 活输入与租约持有到实际读完，取消先记录意图。
- 测量可能干扰处理 → 外部聚合/可关闭观测，单独测自身开销；不作每帧同步磁盘 I/O。
- 参考项目并非可复制交付 → 借鉴机制与用例，若搬代码先确认许可。
- 未有目标设备/模型 → 保留未验项，先完成可独立 CPU/合成链路，不伪造硬件或业务精度验收。

## Migration Plan

先基线再候选，完整小包自查后本地提交；核心来源变更显式修订 sdk-source-revisions.json，保留原提取指纹。回退按提交恢复代码/合同/绑定，不自动回退宿主或替换已发布包。验收与文档随每组同步；OpenSpec 勾选须有当前候选证据。

## MET-2 主目标与保护指标

指标组M-RECOVER，场景S4/S5。故障检测到正确新鲜输出和恢复持续达标的时间、健康流交付、资源趋势及关闭；不以故障期间吞吐或首尾内存替代恢复/稳定性。 对应验收值在下一候选测试前填写目标卡，未标定不捏造百分比或路数；历史已完成项不因改指标自动升级为整包完成。
