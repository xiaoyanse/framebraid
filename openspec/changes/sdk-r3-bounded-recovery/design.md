# Design

BP10域基础索引：句柄表和外持Buffer表沿用每库4096项硬限，首次登记时以fallible精确预留固定连续存储，按地址排序二分查询；不将HashMap桶容量或登记数量当字节计费。基础存储受已冻结项数和类型尺寸共同约束，保留到域卸载，与Context控制载荷预算分列。隔离区沿用4096个token，先淘汰再插入避免4097项增长；域级联关闭以固定32项强引用栈块通知，释放注册锁后调用，不为关闭临时分配所有子项。查询复杂度及满表登记移动成本需要量化，未跑不能假设总体更快；原生/服务体和动态字符串仍另计。

BP10 Context基础登记：内部服务索引固定16个内联槽，关闭钩子固定8个弱引用槽；两库当前分别最多6/3种服务与1/0种钩子，不允许外部任意注册业务服务。登记满额先拒绝，构造失败不发布；关闭使用固定栈快照并释放登记锁后通知。该基础存储在Context创建时已包含，随Context销毁回收，受每库8 Context上限约束；与控制通道载荷/结果预算分列，不虚报为零开销或进程RSS硬限。C ABI及绑定不变；Rust内部Context.services具体类型及CloseHooks注册方式改变，宿主只能经匹配源码消费，不能把内部结构布局当C合同。域句柄、Buffer表和服务体内存另核。

BP12媒体工作线程：Context内共用64个SDK worker槽，与CPU核数分开（含阻塞I/O/回调，不是同时CPU计算数）；新增两个ABI1.1函数及能力位。仅允许收紧0..64，0禁止新建SDK线程，不能强停在用工作；新值低于在用槽返回resourceExhausted而不改变旧值。创建前占槽，spawn失败或实际函数结束归还，取消/超时不提前释放，stats报告本Context活槽和历史峰值。同步调用的宿主线程不计SDK worker；FFmpeg线程数1在已有像素worker执行，不重复计一次。驱动/原生库不受SDK管理的线程明确另列未知，不把本项说成整个进程线程硬限。推理执行器仍用原进程共享预算，不改AM-RT。

媒体抓图索引补查：请求表、合并Flight表、最近图/消费者频率表与连续订阅索引改为可明确计量的有界连续存储；增容先保留新旧重叠，空闲容量计费到State销毁。沿用请求控制项token，存储不另伪造控制项或外持关闭屏障；Flight本体另预付。限额失败不登记不可用请求/Flight、不留下消费者名额；缓存失败须先发布一致失败终态、唤醒合并等待者，再移除本Flight。Closed订阅从活动索引移除，不无限保留仍有外部句柄的旧弱引用。通用服务与全域对象登记另列BP10，不借本项关闭父任务。

推理请求表预算补查：采用有序连续存储以明确实际容量，按已存记录数加本批数量规划，增长前在Context控制字节中同时保留旧、新容量；元数据不冒充外持结果或控制快照，不制造Context关闭屏障。保留已配置记录数量限制及结果TTL，拒绝先于旧请求替换和ID发布；清空仅移除记录，保留容量持续计费到服务销毁。量化准入/等待及容量，不能以取消漏记账换吞吐；媒体记录/服务索引另核，不以本项关闭父任务。

## Context

核对基线 `db0cb1014be04334869bdea914347cd5f060ce71`，范围见 proposal。用户授权 main 串行、阶段测试量化及本地提交，使用 OpenSpec 恢复推进。

## Goals / Non-Goals

目标：全链路有界压力和故障恢复，以 [完整路线](../../../docs/ROADMAP.md) 为范围依据。
不做业务、UI、凭据持久化、第三个 DLL 或扩展池 E1～E4 自动实施，不更改 AM-RT 固定依赖。

## Decisions

H2-STREAM-02执行隔离：在每次网络会话的scoped线程中懒创建一条像素worker，先占既有max_decoders槽并以Arc许可供NativeDecoder重建复用，不新增无预算执行器。原生调用不可强杀，关闭/换会话须等线程返回；没有像素消费者时停止worker，原线程未结束前不新建替代。读线程仅解析参数/参考链与压缩分发，向像素队列移交共享包引用；队列上限取既有AM_Q_ENCODED_STREAM的max_items/max_bytes及冻结上限，元数据/参数副本提前计费，正在执行的一项仍占源总字节。满载清待处理链并递增像素epoch，等待新随机访问点，压缩订阅不受该清理影响。

配置发布和像素出队前的最终校验共用短锁，驱动/构造/回读不持此锁。包的源/配置代次及像素epoch贯穿执行；溢出、配置变化、凭据变化或关闭后旧工作可读完但不能发布为新帧。新配置仍沿R2 H2.3c复用设备，实际执行重新验证；MJPEG逐包独立恢复，不丢压缩参考链。队列占用经现有总queue统计包含，线程界限由decoder许可证明；当前Media通用threads字段的全工作线程覆盖另按1.1审计，不能用零值证明没有工作线程。

复用既有队列、租约和通知线程；先追踪中转所有权，再修预算缺口，不另建后台作业中心。原生库/驱动内存与 SDK 可控预算分开。

ISAPI最近图片缓存按活跃源×频率归属计数，最后同频订阅排空时在归属锁→缓存锁顺序内回收，其他频率继续运行。读取兼容且新鲜的图片后直接共享；需重新采集时写回本订阅频率，不把慢频率新图误写到旧快频率键。leader与follower的两处缓存提交统一检查归属和新旧帧序，防晚完成请求重建已退役键或旧帧覆盖新帧。缓存项受活跃频率数约束，保守HTTP预留不改变，不另建池或更改外部release语义。

推理暂存采用三级字节准入：Context×实时/离线分类账、本 Context 两类合计、共享执行器 64 MiB 总账。分类账含输入复制/保留、在途原生读取与归还屏障，离线规划元数据也预留；RAII 在真实读完后同步归还，取消/终态不能提前腾额度。保持执行器锁→Context 暂存锁的顺序，不在这两把锁内执行复制、回调或原生推理。项数保留现有每槽/单批/域边界，拒绝不产生请求 ID 或保留引用；总额拒绝不得修改任一账本。

Rust H264Hub辅助分发另核：订阅36项与8 MiB载荷双限，配置/重同步控制占项；GOP最多35包（给配置留一项）并保留调用方字节上限。叠层只留最新一项，视频压力先丢叠层；确实溢出再清除受损链，保留当前配置并等待新关键帧，连续两次溢出且无消费则终态关闭，消费清计数。单包超8 MiB以1009/media.packetTooLarge关闭该订阅，不伪称客户端慢。Closed为不可逆屏障，只留一次终态、归还队列引用，不再接数据/配置/叠层。接收先登记Notify等待，再在队列锁内读取消息及终态，防止关闭广播落在检查与睡眠之间或跳过刚入队的关闭原因。C订阅仍走原有独立路径和预算，不将辅助分发改动算作其真实RTSP验收。

复用 R1 预算及 R2 候选；关键安全缺口发现即优先修，不将修复推迟到长跑。

独立解码提交在真正入队后记录接受，QueueFull/ResourceExhausted拒绝只在该提交边界记一次，不能在内层charge与外层API重复累计；参数/句柄/状态及正常无输出信号不作背压。reset只归还当前占用，不清Context累计计数；混合场景的计数单位单列，避免用总accepted推导唯一帧数。

Media数据订阅先用既有控制通道预留对象、最大队列引用槽及预设Vec容量，再预留固定引用队列，避免填满时临时扩容；载荷仍共享原有Arc和数据预算。元数据许可绑定订阅对象全寿命，包含Closed后尚在册/持引用阶段；不能仅清数据队列就归还仍常驻的控制字节。所有构造失败路径自动回收许可，不更改公开结构或允许上调预算。

RTSP Reader兼容新增Rust预算回调：先校验有界长度、计算配置或framing工作区上界，再分配SDK Vec；原有入口保留调用方自行管理的语义。C层的预算Reader把配置保留、转换暂存、载荷分开，成功后从同一预留拆分并归还余量，不对同一载荷重复计费；错误时保留临时许可直到Reader缓冲销毁。探测RTSP走同一适配，HTTP探测按既有4 MiB包络先预留；FFmpeg/网络库内部内存仍单列，不冒充进程RSS硬限。通知队列按实际拥有条目size_of计费，不以16/32字节常量代替包含ControlCharge的条目。

共同评价改用[SDK量化指标与验收目标 MET-2](../../../docs/PERFORMANCE_ACCEPTANCE.md)：区分同路径回归与跨后端资源取舍。每包测前确定主目标、保护指标、计时边界和目标卡，按A/A波动及绝对/相对实际影响评价，不把5%作为统一通过/失败线。原始数据及旧警戒事件保留；功能/安全、机制变化、收益与长期稳定性分别验收。CPU时间、GPU引擎、有效交付及公平性按场景采集，不以单帧耗时替代卸载收益。当前工具和旧预算未改，缺项先按R1新增前置标定；用户已授权恢复；1.0a完成限定像素执行隔离，故障组合与长跑另验。

## Risks / Trade-offs

独立解码配置采用不可变Arc拥有者，复制前占域字节，reset(NULL)只保留引用；每个新解码上下文的参数集缓存另行计费，旧上下文在新构造失败时不释放。Gate更新先无列表校验并规划最终三组参数，准入/分配均成功后一次提交，拒绝保持旧缓存与标志。序列化extra临时副本单独预留并覆盖原生调用寿命。兼容新增Rust同步NAL访问入口，借用只随输入有效；访问者可能看到错误前的部分NAL，调用方在整体成功前不能提交外部状态。旧Vec接口及历史4097个NAL接受边界保留，C ABI不变。

媒体源事件与推理通知采取同类存储原则，但保留源事件丢旧留新策略及64项硬上限：固定存储先占一个控制项和完整槽字节，活事件另占项而不重复计存储字节。排队加忙回调不超已预付槽；满时只丢待处理旧提示，只有忙项则拒绝新提示并记丢弃。未注册不分配；注销/停止等忙回调结束后销毁存储再归还。注册准备、工作句柄锁或线程创建失败不残留许可/新worker，状态查询和数据分发不依赖事件投递成功。

推理通知另核实际队列存储：注册时依据控制项/字节及当前占用计算有界槽数，先以cached_control预留存储额度，再try_reserve_exact；运行期不得扩容。存储许可占一个控制项，活条目再占逻辑项及关闭屏障、字节不重复记；排队+忙回调不超过预留槽数。注销/停止先切断新通知并清条目，忙回调返回后才释放存储；没有回调时不创建队列。很小的控制配置可能明确拒绝注册，不能报成功后永久丢弃全部通知。原生线程/allocator开销仍与SDK字节分列。

- 原生调用不可强杀 → 活输入与租约持有到实际读完，取消先记录意图。
- 测量可能干扰处理 → 外部聚合/可关闭观测，单独测自身开销；不作每帧同步磁盘 I/O。
- 参考项目并非可复制交付 → 借鉴机制与用例，若搬代码先确认许可。
- 未有目标设备/模型 → 保留未验项，先完成可独立 CPU/合成链路，不伪造硬件或业务精度验收。

## Migration Plan

先基线再候选，完整小包自查后本地提交；核心来源变更显式修订 sdk-source-revisions.json，保留原提取指纹。回退按提交恢复代码/合同/绑定，不自动回退宿主或替换已发布包。验收与文档随每组同步；OpenSpec 勾选须有当前候选证据。

## MET-2 主目标与保护指标

指标组M-RECOVER，场景S4/S5。故障检测到正确新鲜输出和恢复持续达标的时间、健康流交付、资源趋势及关闭；不以故障期间吞吐或首尾内存替代恢复/稳定性。 对应验收值在下一候选测试前填写目标卡，未标定不捏造百分比或路数；历史已完成项不因改指标自动升级为整包完成。

独立解码输入队列按有效queue_max_items、时间关联表按原256项边界一次预留，先占控制存储额度；所有条目/空闲容量随Inner拥有。构造新旧上下文重叠均占用，控制不足不启动新原生解码，保留旧状态；不提高64 KiB默认控制预算或承诺所有独立硬限可同时耗满。

RTSP像素中转队列虽已按maximum预留控制字节，但VecDeque惰性倍增可能超出该槽数；改为准入后try_reserve_exact固定槽。时间表原有128项/2048字节额度保留，预留128容量且淘汰在插入前进行，避免129项瞬间触发256容量。最终窗口和PTS关联不变，存储持续持有直到拥有者真实销毁，不调高预算。

连续抓图存储包括引用槽和120项/5秒FPS时间窗口，分配前完整控制准入，固定VecDeque容量，先淘汰再记录；空闲容量仍由Subscription控制许可拥有直到最后引用销毁。先构造队列再占连续消费者名额，注册锁失败归还名额，域对象插入后的订阅登记失败关闭并销毁，不能留下无输出句柄的活对象。原捕获/超时/丢旧及外持图片语义不变。

共享推理执行器按既有domain_infer_slots固定Job引用槽，线程句柄也先预留；Engine本体/槽/句柄和Context索引容量独立记为storage_bytes，与在途暂存共同受既有64 MiB执行器总额限制，不转嫁到某个Context分类账。索引扩容在分配前核旧+新重叠和在途用量，成功销毁旧容器才更新保留额度，移除已退役Weak不提前归还容量。索引登记必须在请求替换、记录插入和ID发布前完成。清理以固定16项栈数组借用Arc快照，在域锁外try_lock各记录表；统计只迭代求和，不收集Vec。公开Context queue_bytes仍为原逻辑数据口径，不冒充全域存储或RSS。
