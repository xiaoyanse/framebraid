# Proposal

> 2026-10-27用户裁决：完整硬件矩阵及固定4h/24h长跑已移出强制验收，不再作为R1～R5收口阻塞，也不改记为通过。保留已有原始证据；功能、失败回退、资源上限、所有权/取消/关闭定向回归及适用量化继续必验。硬件按实际设备和已声明范围记录实测/未测，不要求穷尽全部设备组合。历史“矩阵/长跑仍待”仅描述旧范围，不恢复已撤销门槛。 验收口径以[当前标准](../../../docs/PERFORMANCE_ACCEPTANCE.md)为准。

## Why

已有队列和恢复基础仍需贯穿中转暂存、回调及外部持有验证，确保压力下结果新鲜和可预测恢复。

## What Changes

- 2026-10-26 指标复核采用[MET-2](../../../docs/PERFORMANCE_ACCEPTANCE.md)，本包指标组M-RECOVER，场景S4/S5；故障检测到正确新鲜输出和恢复持续达标的时间、健康流交付、资源趋势及关闭；不以故障期间吞吐或首尾内存替代恢复/稳定性。 用户已授权恢复，按本包任务推进并保留原始证据。

- 全链路有界压力和故障恢复，具体任务及量化条件见 tasks.md。
- 复用既有预算、所有权和 ABI；新增公共能力先同步合同和生成器，保留原冻结历史。
- 原始性能证据只放 .local，公开摘要不包含凭据、设备地址和客户图片。

## Capabilities

### New Capabilities

- `bounded-pipeline-recovery`：全链路有界压力和故障恢复的可验证行为与性能边界。

### Modified Capabilities

无已有主规格；不修改宿主业务或既有公开 ABI 的兼容语义。

## Impact

仅影响 FrameBraid 核心、受影响测试、基准及文档。复用 R1 预算及 R2 候选；关键安全缺口发现即优先修，不将修复推迟到长跑。 不修改 AM-RT，不自动发布或增加平台承诺。
