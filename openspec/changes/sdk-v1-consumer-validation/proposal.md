# Proposal: SDK V1 — 消费方基线与场景测试体系前置

## Summary

把跨团队协作验证有效的"消费方基线+判据自动化"范式前置进 SDK 自身开发流程：
替代方案基线对比进发布门禁、R 系列问题类型沉淀场景测试库首版、发版
checklist 增消费方画像过堂、roadmap 从能力清单迁移到场景清单驱动。

## Motivation

- R 系列七项的根因共性：验证了"做得对"（功能正确），没验证"值得用"
  （vs 消费方替代方案的性能/场景差距）——差距全部由下游配对 harness 暴露，
  SDK 自身门禁无此角
- 协作范式已双方验证有效（同输入 sha256 铁律+判据自动化+P50/P95 口径+
  交付即验），AIeng 判据脚本已入库可参考
- 从"消费方倒逼"变"SDK 自驱"：每个新能力在开发期就知道 vs 基线的位置

## What Changes

- **① 消费方基线门禁**：`scripts/sdk/baselines/` 目录——解码（vs OpenCV
  cv2 配对）、抓图节拍精度（目标间隔 vs 实际 GET 分布）、多路吞吐（1/2/4
  路线性度）。纳入 RELEASE_CHECKLIST 的发版要件（基线漂移=发布阻断）
- **② 场景测试库首版**：`scripts/sdk/scenarios/`——每个已修 R 项沉淀一个
  防回归场景（R1 4K 预算边界/R2 节拍精度/R6 解码性能/R7 MJPEG 流/R8 断流
  可观测/R9 绑定装载完整），合成环境可跑（不依赖真实相机）
- **③ 发版 checklist 消费方画像**：RELEASE_CHECKLIST.md 增"消费方画像"
  节——发版前必答四问（多路形态/主链路协议/分辨率档/认证方式），画像
  决定哪些基线/场景必跑
- **④ roadmap 场景化**：ROADMAP-PLAN.md 增场景视图段（消费方工作流驱动
  的优先级排序，与能力清单并存）

## Impact

- 工具/文档/流程层（scripts + docs），SDK 生产代码零改动
- 基线脚本依赖：OpenCV（python 环境，判据参照 AIeng harness 模式）
- 门禁集成：基线脚本可独立跑（发版手动触发），不进 cargo test（外部依赖）
