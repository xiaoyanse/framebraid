# Proposal

> 2026-10-27用户裁决：完整硬件矩阵及固定4h/24h长跑已移出强制验收，不再作为R1～R5收口阻塞，也不改记为通过。保留已有原始证据；功能、失败回退、资源上限、所有权/取消/关闭定向回归及适用量化继续必验。硬件按实际设备和已声明范围记录实测/未测，不要求穷尽全部设备组合。历史“矩阵/长跑仍待”仅描述旧范围，不恢复已撤销门槛。 验收口径以[当前标准](../../../docs/PERFORMANCE_ACCEPTANCE.md)为准。

## Why

已有可验证热点：逐帧转换上下文、无到期消费者也物化像素、临时浮点数组再复制张量。优先减少确定的开销。

## What Changes

- 2026-10-26 指标复核采用[MET-2](../../../docs/PERFORMANCE_ACCEPTANCE.md)，本包指标组M-HW/M-CONVERT/M-TENSOR，场景S0/S1/S2，必要时S4/S6；硬解优先衡量CPU卸载或固定预算合格路数；转换/张量以无用转换、分配及复制量为主。交付/帧龄、精度/租约和资源是保护指标，不要求硬解每帧快于CPU。 文档收口后用户已授权恢复；S2实际RTSP/混合消费与交付缺口独立留证，保留旧raw及公开ABI。

- 用户于 2026-10-26 将原生解码硬件探测与自动选择从扩展 E2 提升为本轮前置交付项；Windows H.264/H.265 D3D11VA 优先，兼容候选 DXVA2，实际状态及安全回退必须可解释。浏览器 WebCodecs 不属于此原生 SDK 路径。

- 转换、采样与张量热路径，具体任务及量化条件见 tasks.md。
- 复用既有预算、所有权和 ABI；新增公共能力先同步合同和生成器，保留原冻结历史。
- 原始性能证据只放 .local，公开摘要不包含凭据、设备地址和客户图片。

## Capabilities

### New Capabilities

- `frame-processing-efficiency`：转换、采样与张量热路径的可验证行为与性能边界。

### Modified Capabilities

无已有主规格；不修改宿主业务或既有公开 ABI 的兼容语义。

## Impact

仅影响 FrameBraid 核心、受影响测试、基准及文档。R1 基线先成立；不等待 R3 全套长跑才着手局部优化，必要所有权回归本包完成。 不修改 AM-RT，不自动发布或增加平台承诺。
