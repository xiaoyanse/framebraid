# Design

## Context

核对基线 `db0cb1014be04334869bdea914347cd5f060ce71`，范围见 proposal。用户授权 main 串行、阶段测试量化及本地提交，使用 OpenSpec 恢复推进。

## Goals / Non-Goals

目标：转换、采样与张量热路径，以 [完整路线](../../../docs/ROADMAP.md) 为范围依据。
不做业务、UI、凭据持久化或第三个 DLL，不更改 AM-RT 固定依赖；基础硬解探测/选择已由用户明确从 E2 纳入，其他扩展不自动实施。

## Decisions

H2.0b共用策略工厂：新增Rust `CpuDecoder::create_with_policy`，SoftwareOnly不探测、PreferHardware有界选择D3D11VA/DXVA2；报告初始化选择与失败，不将其当实际硬件输出。工厂不重发已接受包，运行期失败恢复留给直接解码/RTSP的随机访问点与代次控制。详细合同见`docs/design/native-hardware.md`；C ABI布局、枚举不变，本阶段不代替H2全局预算与接线。

H2实现前置拆分（2026-10-26）：先提供Rust层显式`media::hardware::probe(api, budget)`，枚举最多8个DXGI适配器，按D3D11VA/DXVA2顺序逐个尝试，最多16次设备上下文创建并立即归还；进程内同时最多1轮探测。报告适配器索引/LUID/名称、编译支持、设备初始化结果与原因；`stream_verified`始终false，因为本入口不解码。预算仅在原生调用之间检查，不承诺强杀已进入驱动的调用。CPU原语/C ABI不因此改变或报告硬解成功，普通查询不触发本入口。后续H2.2～H2.4仍须接上真实帧、自动选择/失败恢复和C ABI诊断演进，不能把设备探测当整组完成。

2026-10-26 范围追加：H2 组在 R1 最小基线后优先，不再将基础硬解探测/选择留在 E2。以现有 FFmpeg 动态库和解码策略接入 D3D11VA，DXVA2 为可用构建下的兼容候选；具体接口演进先评审并同步合同/生成器，保持已有 ABI。查询不偷偷创建会话；显式探测受时间、会话和线程预算限制，设备列表/编译支持不是实码流可用证明。区分设备、依赖、初始化、目标编码/profile/位深与真实输出，返回实际后端而非偏好。探测失败按原因/代次/有限有效期处理，可显式重试，不用永久 OnceLock 锁死瞬态失败。

硬解帧需按格式走硬件传输到 CPU 像素，保持引用和显存预算；回读成本纳入基准。运行期失效需隔离旧代次、保留正在读取的帧、等待关键帧恢复并有界回退。直接数据解码/RTSP 取帧共用策略；压缩直传无解码开销。GPU 设备缓冲跨 SDK 零拷贝、CUDA/QSV 专用解码和其他系统硬解仍为后续。前端 WebCodecs 的硬解偏好/节奏降级不是 SDK 状态；本包不修改 AM-RT，也不宣称修复其页面提示。

先复用 SwsContext，再考虑池；按源/目标格式与尺寸键控并在 Drop 释放。采样与转换需求在同一代次下判定；前处理沿用 u64 对齐拥有者，写 final bytes 而非借用可变全局工作区。

采样前移实施合同：增加无副作用的到期查询，不更新订阅last_frame；只在既有fanout实际选择消费者时推进采样时间。H.264/H.265仍完整送包/接收/丢弃未到期输出以维护参考链，尺寸/健康通知不被采样隐藏；MJPEG保留头部尺寸校验，未到期跳过完整解码。转换前和发布前分别核需求，失败不提前占掉到期机会。不改变C ABI或订阅FPS含义。

RTSP硬件合同缺口登记：既有RTSP源/订阅结构没有hw_policy，不能借用保留字段或把独立decoder配置偷偷套到源。H2.1兼容新增需先定义调用方控制和快照查询，再接RTSP自动选择；保留旧冻结历史。此缺口不以当前CPU采样优化冒充关闭，H2/H5继续优先推进。

R1 基线先成立；不等待 R3 全套长跑才着手局部优化，必要所有权回归本包完成。

共同测量：同机、同输入/模型/运行库/实际后端、同预算与有效交付率，预热后至少三轮；P99 样本不足明确标注。对照前固定容差，先以端到端 P95/有效吞吐不恶化超过 5% 为候选警戒线，超出则调查而非直接放宽；局部提速须超过重复测量噪声。内存/线程服从配置上限，长跑看趋势而非只看首尾。R1 将实际负载、帧龄与截止时间预算补入验证记录后，后包不得事后调整门槛。

## Risks / Trade-offs

- 原生调用不可强杀 → 活输入与租约持有到实际读完，取消先记录意图。
- 测量可能干扰处理 → 外部聚合/可关闭观测，单独测自身开销；不作每帧同步磁盘 I/O。
- 参考项目并非可复制交付 → 借鉴机制与用例，若搬代码先确认许可。
- 未有目标设备/模型 → 保留未验项，先完成可独立 CPU/合成链路，不伪造硬件或业务精度验收。

## Migration Plan

先基线再候选，完整小包自查后本地提交；核心来源变更显式修订 sdk-source-revisions.json，保留原提取指纹。回退按提交恢复代码/合同/绑定，不自动回退宿主或替换已发布包。验收与文档随每组同步；OpenSpec 勾选须有当前候选证据。
