# Design

> 2026-10-27用户裁决：完整硬件矩阵及固定4h/24h长跑已移出强制验收，不再作为R1～R5收口阻塞，也不改记为通过。保留已有原始证据；功能、失败回退、资源上限、所有权/取消/关闭定向回归及适用量化继续必验。硬件按实际设备和已声明范围记录实测/未测，不要求穷尽全部设备组合。历史“矩阵/长跑仍待”仅描述旧范围，不恢复已撤销门槛。 验收口径以[当前标准](../../../docs/PERFORMANCE_ACCEPTANCE.md)为准。

## Context

核对基线 `db0cb1014be04334869bdea914347cd5f060ce71`，范围见 proposal。用户授权 main 串行、阶段测试量化及本地提交，使用 OpenSpec 恢复推进。

## Goals / Non-Goals

目标：转换、采样与张量热路径，以 [完整路线](../../../docs/ROADMAP.md) 为范围依据。
不做业务、UI、凭据持久化或第三个 DLL，不更改 AM-RT 固定依赖；基础硬解探测/选择已由用户明确从 E2 纳入，其他扩展不自动实施。

## Decisions

H2.0b共用策略工厂：新增Rust `CpuDecoder::create_with_policy`，SoftwareOnly不探测、PreferHardware有界选择D3D11VA/DXVA2；报告初始化选择与失败，不将其当实际硬件输出。工厂不重发已接受包，运行期失败恢复留给直接解码/RTSP的随机访问点与代次控制。详细合同见`docs/design/native-hardware.md`；C ABI布局、枚举不变，本阶段不代替H2全局预算与接线。

H2实现前置拆分（2026-10-26）：先提供Rust层显式`media::hardware::probe(api, budget)`，枚举最多8个DXGI适配器，按D3D11VA/DXVA2顺序逐个尝试，最多16次设备上下文创建并立即归还；进程内同时最多1轮探测。报告适配器索引/LUID/名称、编译支持、设备初始化结果与原因；`stream_verified`始终false，因为本入口不解码。预算仅在原生调用之间检查，不承诺强杀已进入驱动的调用。CPU原语/C ABI不因此改变或报告硬解成功，普通查询不触发本入口。后续H2.2～H2.4仍须接上真实帧、自动选择/失败恢复和C ABI诊断演进，不能把设备探测当整组完成。

2026-10-26 范围追加：H2 组在 R1 最小基线后优先，不再将基础硬解探测/选择留在 E2。以现有 FFmpeg 动态库和解码策略接入 D3D11VA，DXVA2 为可用构建下的兼容候选；具体接口演进先评审并同步合同/生成器，保持已有 ABI。查询不偷偷创建会话；显式探测受时间、会话和线程预算限制，设备列表/编译支持不是实码流可用证明。区分设备、依赖、初始化、目标编码/profile/位深与真实输出，返回实际后端而非偏好。探测失败按原因/代次/有限有效期处理，可显式重试，不用永久 OnceLock 锁死瞬态失败。

硬解帧需按格式走硬件传输到 CPU 像素，保持引用和显存预算；回读成本纳入基准。运行期失效需隔离旧代次、保留正在读取的帧、等待关键帧恢复并有界回退。直接数据解码/RTSP 取帧共用策略；压缩直传无解码开销。GPU 设备缓冲跨 SDK 零拷贝、CUDA/QSV 专用解码和其他系统硬解仍为后续。前端 WebCodecs 的硬解偏好/节奏降级不是 SDK 状态；本包不修改 AM-RT，也不宣称修复其页面提示。

先复用 SwsContext，再考虑池；按源/目标格式与尺寸键控并在 Drop 释放。采样与转换需求在同一代次下判定；前处理现直接写u64对齐的独占TensorData，内部可写f32视图重验私有有效长度及dtype/shape，不暴露填充、不借用全局工作区。参数/长度/预算在分配前校验，旧算法仅测试编译，所有字节/变换按位对拍；C ABI/Rust公开面不变。

采样前移实施合同：增加无副作用的到期查询，不更新订阅last_frame；只在既有fanout实际选择消费者时推进采样时间。H.264/H.265仍完整送包/接收/丢弃未到期输出以维护参考链，尺寸/健康通知不被采样隐藏；MJPEG保留头部尺寸校验，未到期跳过完整解码。转换前和发布前分别核需求，失败不提前占掉到期机会。不改变C ABI或订阅FPS含义。

RTSP硬件合同缺口登记：既有RTSP源/订阅结构没有hw_policy，不能借用保留字段或把独立decoder配置偷偷套到源。H2.1兼容新增需先定义调用方控制和快照查询，再接RTSP自动选择；保留旧冻结历史。此缺口不以当前CPU采样优化冒充关闭，H2/H5继续优先推进。

ABI 1.1首组兼容扩展先交付显式初始化探测和context/独立decoder快照查询，详见dual-dll-abi.md §1.1扩展；保留1.0原件，新运行库接受1.0与1.1初始化，能力/实际执行分离。RTSP策略待实际装配时一并新增，首组不导出未被消费的策略设置器，不返回虚构的源报告。

R1 基线先成立；不等待 R3 全套长跑才着手局部优化，必要所有权回归本包完成。

共同评价改用[SDK量化指标与验收目标 MET-2](../../../docs/PERFORMANCE_ACCEPTANCE.md)：区分同路径回归与跨后端资源取舍。每包测前确定主目标、保护指标、计时边界和目标卡，按A/A波动及绝对/相对实际影响评价，不把5%作为统一通过/失败线。原始数据及旧警戒事件保留；功能/安全、机制变化、收益与长期稳定性分别验收。CPU时间、GPU引擎、有效交付及公平性按场景采集，不以单帧耗时替代卸载收益。旧工具/预算保留；用户已授权恢复，S1/S2/S3独立量化已补。S2真实H.264下的30 FPS低交付保留，不以CPU低或脚本退出判通过；采样调度语义不隐式变更。

## Risks / Trade-offs

R2-SAMPLE-01内部修复：复用R3像素worker，在转换前检查到期点，允许各订阅一采样周期内提前物化（最大50ms，最快可服务订阅优先，同速窗口内对齐），转换后用该worker内标准库短sleep分片（每片最多2ms）重验取消并等到实际deadline，随后仍以当前单调时间严格验证每个订阅最短间隔并推进last_frame。时间间隔按纳秒向上取整，不用宽容阈值或平均速率放宽max_fps。等待期间不持配置/订阅锁，已计费私有帧和原生读者保持拥有；新epoch/配置/关闭后不发布。源低帧率/抖动或资源不足时不承诺达到标称值；0=全帧订阅保持不等待自身节拍。此等待只在像素线程，不改变压缩转发/浏览器显示缓冲或C ABI；输出帧龄及额外转换是保护指标，不以多交付的CPU增加判回归。

H2.3c RTSP参数重建：配置变化保留旧NativeDecoder及其额度，暂停像素输出，下一随机访问点以`raw.reconfigure`取得原设备独立引用，不重新选择/创建设备或申请第二个decoder槽。新CPU输出预留和新上下文均成功后才替换；临时新旧上下文重叠不冒充驱动内存硬限。资源拒绝不送新参数到旧上下文，等下一随机访问点；原生错误沿pixel_failure丢弃旧像素上下文并有界CPU恢复。成功后清真实执行状态，保留选择报告和仍在外部持有的旧帧，decode_generation递增；压缩配置变化沿既有Gate处理。闭源/无像素消费者时按原生命周期释放，无新线程或公共ABI。

- 原生调用不可强杀 → 活输入与租约持有到实际读完，取消先记录意图。
- 测量可能干扰处理 → 外部聚合/可关闭观测，单独测自身开销；不作每帧同步磁盘 I/O。
- 参考项目并非可复制交付 → 借鉴机制与用例，若搬代码先确认许可。
- 未有目标设备/模型 → 保留未验项，先完成可独立 CPU/合成链路，不伪造硬件或业务精度验收。

## Migration Plan

先基线再候选，完整小包自查后本地提交；核心来源变更显式修订 sdk-source-revisions.json，保留原提取指纹。回退按提交恢复代码/合同/绑定，不自动回退宿主或替换已发布包。验收与文档随每组同步；OpenSpec 勾选须有当前候选证据。

RTSP r7实际接线采用单拥有者/首次像素订阅前可变策略，同值幂等；共享策略冻结与订阅发布同锁，reuse领取同registry锁。源查询仅复制快照。像素运行错误不重连网络、不清压缩队列、不改压缩配置代次，仅清像素队列并递增decode_generation诊断代次；新随机访问点恢复CPU，不重放RTSP包。R3 1.0a已将同步解码/探测移入有界像素worker，见sdk-r3-pixel-worker-20261026；真实驱动故障P95和长跑仍待；H2.3c已补源参数设备复用；H2.4和读流隔离继续。量化见sdk-r2-rtsp-hardware-20261026，硬件可用不等于更快。

## MET-2 主目标与保护指标

指标组M-HW/M-CONVERT/M-TENSOR，场景S0/S1/S2，必要时S4/S6。硬解优先衡量CPU卸载或固定预算合格路数；转换/张量以无用转换、分配及复制量为主。交付/帧龄、精度/租约和资源是保护指标，不要求硬解每帧快于CPU。 对应验收值在下一候选测试前填写目标卡，未标定不捏造百分比或路数；历史已完成项不因改指标自动升级为整包完成。

正式对照前追加：只对采样订阅，在存在更新待处理包时仅解码参考链、跳过旧帧物化，0=全帧不额外合并。避免把启动/抖动积压按限速播放成旧画面；原生维度/控制观察保留。Windows条件变量粒度的失败原raw保留，改用标准库短sleep，不自旋或改变系统timer设置；OS调度不承诺硬实时。计数器初始化后有界排空预热队列，旧/新同工具测，保留最多一项预热在途的窗口边界说明。
